# WeftCut 草稿迁移与配音对齐

## 当前方案

剪映继续负责生成旁白和维护原始草稿。需要批量缩短旁白间隔时，读取剪映本地草稿中的素材引用、片段范围、字幕文本和时间码，在 WeftCut 中建立独立工程，再用 WeftCut MCP 重建画面、旁白和字幕轨道并调整时间。剪映原稿保持只读，迁移结果不会自动写回剪映。

新增的普通音频素材可以在 WeftCut 单独导入。后续 BGM 应放在单独的 BGM 轨道，保留独立音量和时间位置，不与旁白合并。当前工程已经预留空 BGM 轨，添加时通过 MCP 导入新音频，再放入该轨道。

## 后续操作

### 继续编辑当前工程

1. 确认 WeftCut 打开的项目目录是 `tmp/11月26日正文对齐`。若 MCP 会话重连，先读取 `project://session` 或 `read_project {"view":"session"}`，确认打开目录后再编辑。
2. 编辑前读取 `project://tracks` 或 `read_project {"view":"tracks"}`。轨道和片段 ID 必须以本次读取为准，不复用旧会话记下的 ID。
3. 新增 BGM 时，用 `import_media` 导入用户提供的音乐文件，读取其媒体 ID，再放入已标记为 `BGM` 的音轨。根据用户给的起点和剪辑范围设置时间，不要自动覆盖或混入旁白。
4. 完成多片段批处理后，运行 `check_composition`，检查时间线读回结果；需要时用 `render_frames` 抽查开头、中段和结尾。用 `end_agent_session` 结束批处理，确认保存状态。

### 重建或同步新增内容

剪映新增普通音频或其他素材后，重新读取剪映草稿和素材路径，再导入 WeftCut。当前清单是本轮快照，不会自动跟随剪映变化，也没有增量双向同步。先核对新素材和其轨道时间，再决定把新增内容追加到 WeftCut。若源素材在剪映中使用了 WeftCut 没有对应实现的特效、关键帧或转场，需要接受效果丢失、手工重做，或使用已渲染的媒体保留外观。

## MCP 连接

WeftCut 0.9.0 在本机提供带认证的 MCP 服务。应用安装位置为 `/Users/mac/Applications/WeftCut.app`，其用户数据目录中的 `mcp_auth.json` 保存当前端口和访问令牌。端口或令牌可能变化，连接时动态读取，不把令牌写入文档、日志或仓库。

本轮通过本地 MCP HTTP 端点执行项目操作；当前 Codex 的工具列表没有常驻暴露 WeftCut 专用工具。后续会话若无法调用 WeftCut 工具，需要先让 Codex MCP 客户端连接 WeftCut 的 stdio 启动器（应用内 CLI 的 `weftcut mcp`），或在本机安全读取当前 MCP 认证信息后连接其本地 HTTP 端点。不要使用 computer use 代替 MCP 做常规编辑。首次验证打开、保存、重开时才按用户授权操作界面。

## 边界

- 不直接改写剪映主草稿，也不覆盖或删除其他剪映草稿。
- WeftCut 工程依赖本机 `Media/` 中的已导入素材。只提交本交接文档，不提交 `tmp` 下的工程、媒体、缓存或 WeftCut 安装包。
- 普通音频可以独立迁移；剪映特有的效果器、预设动画和复杂嵌套片段不保证可编辑地迁移。
- 自动生成的对齐是初始整理结果。成片交付前仍需在 WeftCut 检查整段播放、旁白与字幕内容、镜头语义、BGM 混音并导出验收。
