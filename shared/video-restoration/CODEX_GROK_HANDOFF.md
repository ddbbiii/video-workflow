# Grok 交接：把 RealBasicVSR 单镜修复整理成可控工作流

## 目标

把当前验证过的 RealBasicVSR 空间分块路径整理成可复用、可恢复、可验收的本地视频修复工作流，并执行本轮地磁主题已选入成片的视频镜头 VSR 重跑。工作流验证与正式重跑分阶段进行；不得重生成图片、LTX 动态视频或 affine 镜头。

## 审查发现与必须改进项

1. **解除单镜路径绑定。** 当前 runner 和 QA 把源视频、基线、输出名称写死在 c04。改成显式 CLI 参数或单一 JSON 配置，至少提供 `--input`、`--baseline`（可选）、`--output-dir`、`--output-size`、`--model`、`--tile-size`、`--overlap`、`--chunk-size`。启动时打印并保存解析后的完整配置。
2. **避免覆盖并记录失败。** 输出目录必须新建且不存在；在任何推理前写入 `manifest.json`，记录配置、输入文件大小/修改时间、模型标识、Python/Torch/CUDA/FFmpeg/OpenCV 版本、GPU 名称和显存。正常退出写 `completed`；异常退出写 `failed`、阶段、错误摘要和已完成帧数。不要删除失败目录或源产物。
3. **让显存策略考虑当前负载。** 自动选择 tile 时同时查看设备总显存和当前可用/空闲显存；至少预留 2GB 安全余量。首选已验证配置 640x352、overlap 32；空闲显存不足时退到 320x176。捕获 CUDA OOM 后清理缓存、将 tile 长宽减半并重试当前未完成的时间块一次；二次失败则停机并写明原因，不要无限重试。自动降级后的最终参数必须写入 manifest。
4. **进度与可恢复性。** 每个时间块完成后更新 manifest 的帧数和进度，写入日志。若做断点续跑，必须按帧编号写临时无损/低损帧或分段，验证已完成部分后续跑；禁止从一个未闭合的 MP4 猜测最后完成帧。若短期不实现可靠恢复，就明确采用失败后新 run-id 全量重跑，不能声称支持 resume。
5. **补齐硬性输出检查。** ffprobe 检查交付版视频流数、分辨率、帧率、帧数、时长、像素格式、编码和音频流；逐帧完整解码。对有音轨输入，输出音轨必须存在；有意去音轨时需显式参数。帧数与输入一致；时长差小于 0.1 秒；分辨率符合目标。任何硬条件失败，QA 状态必须是 `fail`，不能只写 warning。
6. **修正 QA 状态逻辑。** 当前 QA 即使 `temporal_warning=true`，仍可能给 `pass`；需要让警告进入 `needs_review`，并区分硬失败、自动预警和人工复核。清晰度 Laplacian 只是边缘能量，不可描述为细节真实恢复。建议同时统计中位数、P95、帧间变化和时序指标，并与输入缩放基线比较。
7. **增加 tile seam 检查。** 在 tile 边界带和非边界区域比较局部梯度/亮度差异，输出 seam 指标和疑似边界位置。指标只能预警，必须同时生成首/中/尾帧联系表；至少人工查看联系表和完整播放结果后才标记 `visual_qa=passed`。没有人工播放时状态保持 `pending_review`。
8. **保留回退选择。** QA 不通过时保留 VSR 文件用于诊断，但推荐交付状态选 Lanczos 基线；若基线缺失则只报告失败，不擅自把有问题的 VSR 版标成可交付。

## 推荐实现边界

- 继续复用现有 RealBasicVSR 模型、空间重叠加权拼接和 FFmpeg 编码路径，不要换模型或改变已验收画面风格。
- 将“运行推理”和“运行 QA”拆成独立命令；QA 可对现有资产只读运行。
- 用短 smoke test 验证参数解析、manifest、帧写入、拼接、音频映射和 QA 状态；smoke test 限制为 2-3 帧。正式重跑按下方本轮任务执行，不可覆盖 `20261007-vsr-baseline-c04-spatial-full`。
- 不要触碰 GPU 队列状态、项目源素材、原视频或 Lanczos 基线。

## 本轮地磁主题的实际重跑任务

这次交接明确包含正式 VSR 重跑，不限于工具改造。处理范围是“当前地磁主题最终剪辑中已经选用的真实生成视频镜头”，不是所有历史 run 目录中的 mp4，也不是 affine 推拉平移镜头。

1. 先从项目的最终剪辑清单/镜头表读取真实视频镜头及其最终选用的源文件，生成 `vsr-input-manifest.json`。每项至少有镜头 ID、源文件绝对路径、帧数、时长、帧率、尺寸、音轨状态和对应 Lanczos 基线（若有）。不得按文件名猜测、把 overview/联系表当源片，或把失败尝试/旧版本混入清单。
2. 若项目没有明确标识“最终选用真实视频镜头”的剪辑清单，先只完成扫描和候选清单，停止正式 GPU 重跑并报告歧义；不要擅自把历史目录所有视频都跑一遍。
3. 完成阶段 A/B 的无 GPU 测试及单次 2–3 帧 GPU smoke test 后，先对 c04 全长跑一次新工作流，输出到全新、唯一的 run 目录。与已验收 VSR 和 Lanczos 基线比较并完成人工播放检查；不要覆盖旧版。
4. c04 通过硬性 QA 且人工确认无明显闪烁、接缝、变形、音画问题后，再按 `vsr-input-manifest.json` 顺序串行处理其余清单镜头。每个镜头独立写 manifest、日志和 QA；一个镜头失败就暂停后续批次并报告，不要自动循环重试。
5. 所有输出保持在新的 `runs/<日期>-vsr-rerun-<批次ID>/` 目录，不覆盖源片、原 Lanczos 版、旧 VSR 版或其他 run。目标交付 1920x1080；输入有音轨则保留，无音轨则保持无音轨。
6. 本轮 GPU 重跑由 Grok 明确串行执行，不经 GPU 队列，不得删除、伪造或抢占共享 GPU lock。启动前确认无其他 GPU 任务/lock；任务结束确认本进程 lock 已释放。遇到已有他人 lock 时停止并报告。
7. 交付时附输入 manifest、逐镜输出路径、耗时、QA 状态、失败项和人工播放状态。自动 QA 通过但尚未人工播放的镜头仍标 `pending_review`，不能宣称整轮最终验收完成。

## 给执行者的具体顺序

按以下顺序提交改动；每一阶段通过后再进入下一阶段。不要一上来改模型推理算法。

### 阶段 A：配置和安全门

1. 先备份将要修改的脚本到同目录 `backup/`，文件名带时间戳；不要备份视频资产。
2. 把 runner 改为 CLI 配置。必须拒绝缺失输入、非视频输入、输出目录已存在、tile/overlap/chunk 参数非法、FFmpeg/ffprobe 不存在等情况；在创建输出目录前完成静态参数校验。
3. 支持 `--dry-run`：只解析配置、探测输入和环境、打印将运行的完整命令/参数，不加载模型、不占 GPU、不建正式输出目录。
4. 正式运行时先用排他创建新 run 目录，再立即写 `manifest.json`。每次状态更新都采用临时文件写入后原子替换，避免中断留下半截 JSON。

### 阶段 B：失败可诊断、输出可验收

1. runner 顶层捕获异常；无论在哪个阶段失败，都尽力写入 `status=failed`、`failed_stage`、异常类型/摘要、已完成帧数和日志路径，再以非零退出码结束。不得吞掉异常。
2. 每个时间块成功写入后更新 manifest 的 `frames_completed` 和进度；日志记录 tile、chunk、帧范围、耗时和显存。不要实现含糊的 MP4 断点续跑。当前版本统一规定失败后使用新 run-id 全量重跑。
3. 区分 `qa_status` 与 `visual_qa`：机器硬检查失败为 `fail`；机器检查通过但有时序/拼接预警为 `needs_review`；无预警也只能是 `pending_review`，直到人工查看联系表并完整播放后才允许 `pass`。
4. 先运行静态和小型 CPU 测试。通过后最多跑一个全新目录的 2-3 帧 GPU smoke test；确认不会覆盖已完成 c04 成果，也不会留下 GPU lock。通过后按“本轮地磁主题的实际重跑任务”执行 c04 全长验证和清单内镜头的串行 VSR 重跑。

### 阶段 C：交付执行说明

交接完成时，在回复里给出以下内容，不能只说“已完成”：

- 修改文件清单和每个文件用途；
- Grok 实际运行过的命令及退出码；
- dry-run、失败注入、音频映射、解码检查、GPU smoke test 各自的证据；
- 新工作流的正式调用示例；
- 未实现的断点恢复、人工视觉检查等限制；
- 明确声明处理了哪些镜头、是否有镜头因歧义或失败而暂停，以及没有重生成哪些资产。

## 具体实现注意事项

- 当前 `run_vsr_streaming.py` 的配置仍通过模块常量和环境变量绑定到 c04；`qa_single_vsr.py` 也将输入、基线和输出目录写死。不能把 `VSR_WORKFLOW.md` 中“可复用”的描述当作代码已经实现。
- 当前 runner 只有成功路径写 `status=completed`；模型加载、推理、编码或解码中途异常时，manifest 会停留在 `running`。这必须修复，且失败退出码要非零。
- 当前 runner 使用 `-y` 编码输出并用 `-shortest` 合并音轨。新实现应依靠“唯一且预先验证不存在的 run 目录”避免覆盖；对输入音频时长需验证输出音画同步/时长，不能只依赖 `-shortest`。
- 当前显存选择只看 GPU 总显存，没有按当前空闲显存预留安全空间，也没有 OOM 的一次性降级重试。
- 当前 runner 在主程序外创建共享 GPU lock。保留项目现有互斥语义，并在进程异常退出时记录 lock 清理策略；禁止删除不属于本进程的 lock。
- 当前 QA 只检查视频帧数、音轨、时长和解码；没有校验目标分辨率、帧率、编码/像素格式，也没有 tile 接缝指标或联系表生成。增加的指标应是诊断信息，不能宣称 Laplacian 数值证明真实细节恢复。
- 当前 QA 的 `temporal_warning` 不参与 `qa_status` 的计算，硬检查之外的状态也不是可靠三态。必须按上面的状态规则修正。
- 音轨映射应遵循输入：存在音频就保留并检查；不存在音频就允许无音轨输出；只有显式 `--drop-audio` 才允许丢弃原有音轨。

## 最小验收命令矩阵

Grok 应把等价命令写入 README/工作流文档，并提供真实执行结果。具体参数名可随 CLI 设计调整，但覆盖行为不得减少。

| 场景 | 预期行为 |
|---|---|
| `--help` | 非零错误不发生，显示全部参数和默认值 |
| 有效输入 `--dry-run` | 0 退出；显示规范化配置；不加载模型、不创建 run 目录 |
| 输入缺失 / 视频不可解码 | 非零退出；说明失败阶段；不启动推理 |
| 输出目录已存在 | 非零退出；目录内容和时间戳保持不变 |
| 非法 tile、overlap、chunk | 非零退出；在加载模型前拒绝 |
| 注入模型加载或编码异常 | 非零退出；留下 `status=failed` manifest 和日志 |
| 2-3 帧 smoke test | 新目录中有输出、manifest、QA、联系表；帧数/分辨率正确；音轨规则正确；完成后 GPU lock 已释放 |
| smoke test QA | 自动 QA 不得把结果标为人工验收通过；无播放时为 `pending_review` 或 `needs_review` |

## 最终验收

- 从另一段明确指定的本地视频可以仅通过 CLI/配置运行，不需要改 Python 源码里的路径。
- 缺输入、输出目录已存在、FFmpeg 不存在、模型加载失败、OOM、音频缺失、帧数/时长/尺寸不符等情况都能给出非零退出码或明确 `fail` 状态，且留下 manifest/log。
- 正常结果包含 raw 修复视频、1080p 交付版、manifest、QA JSON、联系表和日志；原音轨被保留。
- 自动化 QA 不把未人工播放的视频标为最终通过。
- 提供变更文件列表、运行命令、测试证据、未解决限制；不声称做过未实际执行的 GPU 或视觉测试。
