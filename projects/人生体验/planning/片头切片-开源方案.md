# 片头「切片」：开源方案调研（2026-11-10）

> 目标：把参考片 0–2 s 的「一张主视觉切成矩形块、逐块展开」做成可复用、可批量、可后期调参的工序，并给出不依赖剪映/CapCut 的开源路线。
> 结论先行：**本机用 FFmpeg + Python（Pillow/NumPy）自建合成脚本最合适**；需要浏览器预览时用 Revideo（MIT）；需要手动改时用 OpenCut（MIT，classic）或 Kdenlive/Shotcut。Remotion 源码可用但**有商业授权限制**，不作为默认。

## 一、先把「切片」说清楚

这个词有两种常见意思，方案完全不同：

| 说法 | 实际动作 | 本片是否需要 |
|---|---|---|
| **画面切片 / 拼贴** | 把一张图切成 5–7 块矩形，逐块展开、错位滑入，配 RGB 撕裂 | **是**，参考片片头就是这个 |
| **素材切片 / 自动剪碎** | 把长视频按镜头/静音切成短片段，再挑片段 | 本片头不需要；将来做「直播切片」「长片拆条」才用 |

下面 A 部分解决「画面切片」，B 部分解决「素材切片」，别混。

## 二、A. 画面切片：方案对比

| 方案 | 许可 | 能做什么 | 适不适合本片头 | 代价 |
|---|---|---|---|---|
| **FFmpeg**（`crop` / `overlay` / `rgbashift` / `noise` / `tmix` / `xfade`） | LGPL/GPL（按编译选项） | 裁切、叠加、通道错位、噪点、拖影、转场；可纯命令行 | **适合做底层**，但 6 块面板各自定时展开用 filtergraph 写会很绕 | 无新运行时；表达式难维护 |
| **Python + Pillow + NumPy + FFmpeg** | Pillow（HPND/开源）、NumPy（BSD）、FFmpeg | 逐帧合成：面板几何、缓动、撕边、条带位移、文字层都能精确控制；再交 ffmpeg 编码 | **最合适**：本机已有 Python/Pillow/NumPy/ffmpeg，1080p/30fps 的 5.4 s 只要 162 帧 | 需要自己写脚本；每帧 Python 合成约 0.1–0.3 s |
| **MoviePy** | MIT | Python 视频剪辑、合成、文字；API 友好 | 可以做，但逐帧像素级故障效果不如 Pillow/NumPy 直接；v2 有破坏性变更 | 多一层依赖；性能一般 |
| **Revideo** | MIT | TypeScript 写场景，headless 渲染，React 预览；适合程序化视频 | 适合需要**浏览器实时预览**、多人协作时 | 引入 Node 工具链；本机现有 Python 管线要多一套 |
| **Motion Canvas** | MIT | TypeScript 生成器动画，实时预览，偏信息动画 | 适合做章节卡/文字动效，不适合像素级故障 | 同上；生态偏 2D 矢量 |
| **Remotion** | 特殊许可（公司规模/商用需付费） | React 写视频，生态最大 | 能力够，但**许可不适合默认生产** | 先读 `remotion.dev/license`；有法务成本 |
| **OpenCut** | MIT | 开源 CapCut 替代，Web/桌面/移动 | 适合手动剪、改时间线；重写版尚未完成，classic 可用 | 不是批处理引擎；自动化要等其 API |
| **Natron** | GPL-2.0 | 节点式合成，做面板/故障/文字都可以 | 能做，但 GUI 节点工程不适合批量与版本管理 | 学习成本高；每期手动搭 |
| **Blender**（VSE / 3D 平面） | GPL | 3D 面板、摄像机、合成 | 只有做「面板有透视/三维运动」时才值得 | 重；渲染慢；杀鸡用牛刀 |
| **Glaxnimate** | GPL-3.0 | 开源 2D 矢量动画，做标题/图形动效 | 适合做章节卡的矢量字动画 | 不做像素故障；要导出序列 |
| **Kdenlive / Shotcut** | GPL-2.0+ | 开源 NLE，手动剪辑/关键帧 | 备选；手动拼 6 块面板很累 | 不适合批量 |

### 2.1 结论

0. **没有找到可直接套用的开源模板**：检索到的都是通用合成/剪辑工具（FFmpeg、MoviePy、Revideo、OpenCut、Natron 等），没有专门复刻「一张图切 6 块逐块展开」的现成项目。因此按「自建脚本 + 通用工具」处理，不追模板。
1. **主路线：`shared/compositing/slice_intro.py`（Pillow + NumPy + FFmpeg）**。理由：本机已具备、时间精确到帧、参数全在 JSON/Python 里、可版本管理、可批量套每期文案；1080p/30fps/5.4 s 的合成量很小。
2. **预览路线：Revideo（MIT）**。如果以后想在浏览器里拖时间线、给别人看，Revideo 比 Remotion 许可干净；但它要 Node，不作为一期默认。
3. **手动路线：OpenCut classic 或 Kdenlive**。只用于临时改一两帧，不进生产线。
4. **不默认 Remotion**：源码可见 ≠ 可商用；公司规模超限要买 license。
5. **不用剪映/CapCut 模板**：不是开源，模板与素材授权不清，且无法批量参数化。

## 三、A. 推荐工序（可落地）

```text
主视觉 PNG（2048×1152，无字）
  → slice_intro.py
      1. 读 6 块面板配置：源矩形 / 目标矩形 / 起始时间 / 展开时长 / 方向 / 缓动
      2. 逐帧（1920×1080 / 30fps）：
         - 黑底
         - 每块从 1–3 px 细缝长到目标矩形，带 3–10 px 滑入位移
         - 撕纸白边 1–3 px
         - 全画面 RGB 错位、横向条带位移、噪点、扫描线、暗角、1.00→1.03 推近
      3. 叠红字钩子 / 关卡卡（毛笔字 + 灰残影 + RGB 分离）
      4. 输出 PNG 序列
  → ffmpeg -framerate 30 -i %04d.png -c:v libx264 -crf 18 -pix_fmt yuv420p
  → 音频：drone + 3 记 hit + 撕裂噪声 + 口播
```

### 3.1 面板参数（对应参考片）

| 参数 | 建议默认 | 可调 |
|---|---|---|
| 面板数 | 6（5–7） | 4–8 |
| 黑缝 | 6–20 px | 4–30 |
| 展开时长 | 0.25–0.60 s | 0.15–0.8 |
| 错峰 | 0.06–0.12 s | 0.03–0.2 |
| 起始细缝 | 1–3 px | 1–6 |
| 滑入位移 | 3–10 px | 0–20 |
| 撕边 | 1–3 px 浅灰 | 0–4 |
| RGB 错位 | ±8–20 px | ±4–30 |
| 条带位移 | 2–8 条，±6–30 px，6–15 Hz | 可关 |
| 噪点 | 3–8/255 | 0–12 |
| 暗角 | −15–25% | 0–35% |

### 3.2 为什么不用纯 FFmpeg filtergraph

`crop` + `overlay` + `enable='between(t,...)'` 可以拼，但每块面板的「从细缝长到目标大小」需要 6 组 `scale`/`crop`/`overlay` 表达式，还要错峰；一旦改面板数或时长，整条 graph 要重写。Python 逐帧合成把几何写在数据里，改参数不用改滤镜链。

## 四、B. 素材切片：如果以后要「剪碎长片」

| 工具 | 许可 | 用途 | 备注 |
|---|---|---|---|
| **PySceneDetect** | BSD-3-Clause | 按内容检测镜头切点，可 `split-video` 直接切 | 本机未装；`pip install scenedetect`；依赖 ffmpeg/mkvmerge |
| **auto-editor** | Public Domain | 按静音/运动自动去死气，导出 Premiere/Resolve/Kdenlive/EDL | 适合口播粗剪，不适合画面切片 |
| **LosslessCut** | 见仓库 LICENSE | 手动无损切/合并 | GUI；适合挑素材，不适合批量 |
| **Kdenlive / Shotcut** | GPL-2.0+ | 手动 NLE | 备选 |

> 本次不做「素材切片」。如果将来要把 11 分钟参考片拆成章节素材，用 PySceneDetect 的 `ContentDetector` 比 ffmpeg `select=gt(scene,...)` 更稳，且能直接导出切点表。

## 五、许可与合规（写进规则的硬线）

1. **参考片只用于拆解**，不把任何一帧、任何音轨放进成品；切片主视觉必须是我们自己生的图。
2. **Remotion** 默认不用；要用先确认公司 license。
3. **剪映/CapCut 模板**默认不用；模板素材与字体授权不可控。
4. 字体单独授权：毛笔标题字不能用未授权字库；当前可用 `MaShanZheng-Regular.ttf`（OFL）加粗模拟，正式字族待定。
5. 开源工具只解决「怎么做」，不解决「素材从哪来」；主视觉仍走 `new1` / `old` 生图与角色锁。
