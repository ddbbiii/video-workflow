# 《你是一只蟑螂》24小时成片优化方案

日期：2026-10-10
适用范围：本集当前已完成的静帧、配音、I2V 和 affine 资产

## 目标

在不重新生成现有媒体的前提下，先产出可审成片草稿，再完成 clean/sub 两个交付版本。处理后口播是时间真源，目标把从本文件开始执行到交付控制在 24 小时内。

## 固定决策

- I2V 使用已有 lanczos 版本；`visual_qa=pending` 的镜头可以先进入草稿，但不得伪称人工通过。
- 争议或缺失媒体优先回退对应 affine；不临时改变叙事，不为凑时长拉伸 I2V。
- 每个镜头的类别保持二选一：`image_to_video` 或 `image_camera_motion`。使用 V1/V3/V5-C/V7-C/P1/P2 白名单；一次首尾叠化循环合法，旧交接中的一律禁止循环已过时。没有锁定循环计划的本集镜头默认不循环，不让执行者临场决定叙事逻辑。
- 片头第三句在正文时间轴确定后一次 resolve；不先猜分钟数再返工。
- 先章节落盘，最后只做一次整片编码；局部修改只重渲染受影响章节。

## 执行顺序

1. 从 `audio/vo-processed/atempo07304/manifest.json` 和分章音频生成 `timeline.json`，记录 utterance、章节、起止时间、目标镜头和所需时长。
2. 由 `SHOT_PLAN.json`、I2V manifest、affine manifest 生成 `media-map.json`。每条记录包含 `shot_id`、`shot_class`、媒体路径、可用秒数、选用理由和回退路径。
3. 先算时长覆盖，再拼章节草稿。已有约5秒 I2V、7秒 affine 不视为足够：I2V 不足覆盖目标镜长且没有预定合法延长时，整镜回退对应原图，按目标镜长重新渲染 P1；不在同镜接原图补足。已有 affine 够长可截取，不够长则按最终镜长重渲染，禁止重复播放7秒片段。保留所有旧素材，记录分类变更和实际动态占比。
4. 可并行生成字幕草稿、BGM stem 和混音预览，但草稿字幕只用于章节检查。正式字幕不得沿用“长句拆行平均分配时间”的脚本结果；片头接入、最终纯旁白和全片timeline锁定后，统一以完整音轨实际发音边界生成正式SRT/ASS，再烧录sub版。
5. 片头使用正文实测时长 resolve，接入章节草稿；片头无 BGM，正文 BGM 使用统一曲目并按规则增益。
6. 对章节草稿做完整解码、音画时长和黑帧检查，再输出整片 clean 和 sub。
7. 最终只记录需要人工复核的 I2V 清单；不因少量待审镜头阻塞可审版本。

## 并行边界

- CPU 可并行：时间轴、字幕、BGM 混音、affine 渲染、章节拼装、ffprobe 检查。
- 已完成 GPU 资产只做必要处理；不要重复提交 90 条 I2V。
- VSR 不阻塞可审草稿，Lanczos 只作为草稿候选，不代表用户已批准降低正式高清标准。草稿时间轴锁定后仅处理最终选入的动态，正式版沿既有高清要求；修复未完成则记录未完成，不把草稿冒称正式成片。

### 强制并行安排

Grok不得把下列工作排成一条长队：

| GPU主线 | CPU、磁盘和图片接口并行线 |
|---|---|
| 分批处理 I2V 或 VSR，遵守 GPU lock | 生成 timeline 和 media-map |
| 一批 GPU 任务结束后立即启动下一批 | 生成字幕 timing 和 ASS/SRT |
| GPU 运行期间 | 渲染 affine、准备章节拼装、生成 BGM stem 和混音预览 |
| 某章动态完成后 | 立即拼该章草稿、做 ffprobe 和章节 QA |

同一 GPU 仍保持单任务互斥；并行指 GPU 主线与 CPU/图片接口线并行，以及独立章节的 CPU 任务并行。每个后台任务必须记录 PID、日志和输出目录。CPU 持续低于约30%且没有磁盘或 GPU 瓶颈时，检查是否漏启动可并行任务。

## 最小检查点

每个阶段更新 `runs/<run-id>/CHECKPOINT.json`，只写：`stage`、`completed`、`running`、`next_action`、`blocked`、`updated_at`。写入采用临时文件替换。

Grok 中断后先读取 checkpoint、timeline、media-map 和实际文件，再从未完成项继续；已存在且可用的文件不得重做。普通阶段完成后直接进入下一阶段，不等待再次确认。

## 交付物

- `timeline.json`
- `media-map.json`
- 分章节草稿及 manifest
- `narration-dry.wav`、`bgm-stem.wav`、`mix-master.wav`
- clean 版与 sub 版整片
- `FINAL_QA.json` 和待人工复核的 I2V 清单

## 回退

I2V 出现明显结构变形、闪烁或无法完整解码时，保留原文件和 QA 记录，media-map 改用对应 affine。不得删除源文件，不得把自动检查写成人工通过。

## 时间口径

本集从已有资产继续拼装，首版草稿暂估3–6小时，正式版追加高清处理、复核和导出暂估3–8小时；均非实测承诺。动态占比降低必须在报告中明确，不能把90条生成成功等同于90条均进入正式片。新集24小时预算从文稿、分镜和提示词锁定开始，写稿讨论、首次环境改造另计。
