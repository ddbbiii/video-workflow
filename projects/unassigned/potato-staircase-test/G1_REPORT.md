## 0. 结论先行

1. **3 土豆接力在纯物理下可以做出来**，而且每个土豆正好下落**一级**（不是跳级、不是被按住释放）。
   配方见 §4，证据见 `g1/D/`。
2. **参考片的阶梯比例在纯物理下不可能接力。** 踏面 88px、土豆半径 24→62px 时，相邻两颗土豆的间隙只剩
   33px 和 17px；落下来的土豆只能砸在下一颗的**肩部**（撞击法线几乎垂直，nx≈-0.35~0.34），
   拿不到水平冲量。A/B/C 三个变体全部失败，A 的土豆甚至直接跳过两级落到第 4 级。
3. **挡边（前沿小凸起）这条路上限很低。** 挡边能可靠地把土豆停在踏面前沿，但它同时是一道必须爬过去的坎：
   被撞者要 77px/s 才能翻过 4px 挡边，实测只拿到 38px/s（E 变体）。
4. **10 级也能全被动跑完**，前提是把踏面加宽到 ≈3.2×最大半径、并让土豆停在踏面前沿的临界点：
   `W=200 / frac=0.985` 时 **9/9 全部接力成功**，15.2s 走完（预演数据，见 §5）。
   同条件下参考比例的 10 级走**只撑 2 级**就停。
5. 代价：踏面 200px 的 10 级阶梯横向 2000px，**装不进 1080 竖屏**，G3 必须解决构图（旋转约 50° 或 0.52 缩放）。

## 3. 参考比例为什么必然失败（这是核心发现）

纯物理接力的几何要求，用一行不等式就能写清：

```
落点 L + r_被撞 + r_撞人  <  接收者位置 R ≤ 踏面宽 W
其中 L = v_horizontal × sqrt(2·H/g)      （从台阶边缘飞出到落地）
```

代进参考片比例（W=88, H=125, r=24→40, v≈180）：
`L ≈ 180×0.48 = 86px`，而 `W − r_撞 − r_被撞 = 88 − 24 − 31 = 33px`。
**落点已经越过整块踏面**，所以只有三种结局：

- 土豆**飞过头**，直接落到下一级甚至下两级（A/C 的 `seq={0:[3]}` 就是跳过 1、2 级）；
- 或者**砸在下一颗的肩部**，法线塌成近垂直（nx=-0.35~0.34），冲量被地面吃掉，被撞者只拿到 0.9~25px/s；
- 或者被挡边卡死（B/C/E）。

对照参考片里"土豆几乎占满踏面"的构图：最大的那颗半径 62.5，两颗相邻的半径和 120.5 **已经大于踏面 93**。
也就是说参考片里**下一颗土豆根本没地方站** —— 这基本可以确认参考片是手绘/隐藏约束动画，不是刚体解算。
（交接文档 §3 的判断是对的，现在有数据了。）

**惩罚项**：把踏面加宽到 200 之后，nx 从 ±0.35 直接变成 +1.00，被撞者从 14.7 涨到 40.5。
同一个物理引擎、同样的初速，唯一的区别是"落点后面有没有站人的地方"。

## 4. D 的配方（可复现）

```python
step_w = 200      # 踏面宽，≈3.2 × 最大半径
step_h = 150      # 级高
radii  = (24, 30, 37.5)
slope  = 0        # 水平踏面
lip    = 0        # 无挡边
receiver_frac = 0.985   # 接收者中心 = 踏面左端 + 0.985×W，即距前沿 3px
push_v = 180, push_roll = True   # 初速按纯滚动给（ω = v/r），避免滑动摩擦吃掉 1/3 动能
roll_resist = 10  # 滚动阻力 px/s²，真实土豆会自己停住
```

三条关键点：

1. **水平踏面 + 无挡边**：土豆静止时不滚（$\tan\theta = 0$，没有力矩），滚动完全由撞击驱动。
   实测滚动指数 0.06（`v_x − ωr` 归一化），是真的在滚，不是贴图假转。
2. **接收者停在踏面前沿的临界点**（球心距边缘 3~5px）：只需要很小的水平冲量就能把它推下去，
   所以接力能撑很久。它同时解决"接力会衰减"的问题——被撞者不需要跑完一整块踏面。
3. **不能有挡边**：挡边是"静止必需的坎"，也是"接力致命的上限"。4px 挡边要 77px/s 才翻得过去，
   实测最好只有 38px/s（E）。拦得住、也放不走。

| 配置 | 接力 | 撞击 | 时长 | 落地序列 | 剩余失败项 |

| W=200, frac=0.985 | **9/9** | 10 | 15.2s | **每个都只下一级** | 撞击后分离（有 1 对勾着滑行） |
| W=200, frac=0.97 | 9/9 | 37 | 25.0s | 第 7 颗连跳 4 级 | 撞击后分离 |

- **好消息**：全被动 10 级接力存在，且只用 15.2s 仿真。

  比 45–60s 的目标短，需要靠片头、镜头停留、结尾来补，或者把重力调低做整体慢节奏。

## 6. 与参考片的差距（G3 要面对的）

1. **构图装不下**：W=200 的 10 级横向 2000px + 竖向 1500px，1080×1920 竖屏放不下。
   两条路：(a) 整体旋转 ~50°（参考片本身就是斜向下的，最合适）；(b) 相机缩到 0.52（土豆会显得偏小）。
   建议 (a)，G3 用相机变换实现，物理世界坐标不动。
2. **动作质感不同**：参考片是"滚过去撞"，我们的物理是"点一下就掉下去"。因为接收者站在临界点，
   被撞后立刻翻下去，位移很短。慢放 + 镜头推近 + 音效可以补足"撞击感"，但动作本身不会一样。
   如果想要"滚过去撞"的观感，就得把接收者放回踏面中部 —— 那就回到 A 的死局。
3. **土豆数量 vs 踏面宽度**：参考片的踏面比土豆窄，我们要 3.2 倍。二者不可兼得。


踩坑记录：

- **pymunk 7 没有 `Arbiter.relative_velocity`**（交接文档只提了 `add_default_collision_handler` 和 `current_time`），
  得自己用接触点算相对速度。
- **没有 CCD 的代价是真实的**：第一版右端挡墙只画在踏面高度以下，土豆直接从踏面滚过墙顶飞出世界
  （坐标跑到 x=2317、y=82052）。挡墙必须**高出踏面**，并且所有边界要闭合。这类"世界的洞"是静帧看不出来的，
  只能靠坐标越界检查抓。
- **静止位不要靠 settle 撞出来**：用解析解直接放（挡边凹处的楔形平衡 `d = -sqrt(2rR+R²)`），
  静止漂移才能稳在 0.00px；靠"掉下去再稳"会在挡边上弹 26px 才停。
- **初速要给纯滚动**：直接给线速度、让摩擦力把滑动转成滚动，会白丢 1/3 动能（v → 2/3 v），
  接力因此少走一级。
