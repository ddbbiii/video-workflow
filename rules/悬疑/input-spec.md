# 悬疑 · 单集输入契约 v2.0（纯正文）

> 2026-11-07 新建；2026-11-14 按「纯正文」口径收敛：删片头、配音、字幕烧录、成品库字段。
> 与 `rules/助眠解说/input-spec.md` 结构对齐，字段按悬疑线重写。
> 收到新单时：先按 §0 走填写单，再按 §4 默认值开工。

## 0 使用方式

1. 复制 `shared/workflows/悬疑/EPISODE_INPUT_TEMPLATE.md`，另存为 `INPUT_<slug>.md`，放进单集目录。
2. 填 8 项必填（标题 / 母题 / 故事主线 / 主次悬念与反转 / 三条物证 / 结尾 / 来源与授权 / 目标时长）；4 项选填（必须覆盖 / 必须避免 / 参考材料 / 备注）。
3. 把文件路径发我，附一句"按 input-spec 执行"。

校验这 8 项；不合格只列问题清单，不上手写稿。通过后先出故事主线大纲、悬念预算表与总字数预算（§6），再进写稿。

## 1 三步

1. **定稿题材**：故事母题一句话，加"主悬念 / 次悬念 / 反转"三行。
2. **定来源**：原创、公版重构、外部素材（Reddit / SCP / 书籍 / 新闻），外部素材必须写授权状态。
3. **定长度**：目标时长 8–20 分钟，换算成旁白汉字数（见 `narrative.md`）。

## 2 必填（八项）

| 字段 | 说明 |
|---|---|
| 标题 | 4–40 字；不能写"待定 / 由你拟 / 无" |
| 故事母题 | 一句话，不超过 40 字；必须能直接复述"谁遇到什么异常、做了什么、付出什么代价" |
| 故事主线 | 按事件/情节点写，≥6 个节点；标出反转与每条物证落在哪个节点；不按段、不标时间、不拆字数 |
| 主悬念 / 次悬念 / 反转 | 三行；主悬念一个，次悬念最多一个；反转写清"哪条证据改写了前面哪个理解" |
| 三条可拍物证 | 每条 = 具体物件 + 在哪个节点出现 + 印证什么；至少一条要改写理解 |
| 结尾 | 停在哪个画面或哪句话；保留 1–2 个未知 |
| 来源与授权 | `原创` / `公版（写明出处与公版状态）` / `外部素材（作者、链接、授权状态）` |
| 目标时长 | 8–20 分钟，默认 15；同时给出总汉字数（不拆段） |

- **本线不做片头**：成片 0 秒即正文第一帧，没有钩子卡、标题卡、账号卡。
- 选填四项（填写单第 9–12 行）：必须覆盖 / 必须避免 / 参考材料 / 备注。

## 3 授权状态

- `original`：原创，无外部权利问题。
- `public-domain`：公版母题，须从公版原文重新原创。
- `authorization-pending`：外部素材已选定但未取得许可——只能做改编提案与结构，不得写锁定稿、不得进生产。
- `authorized`：已取得书面许可，附许可范围。

**2026-11-09 用户接管授权**：用户明确"授权的事我会搞好"；助手不再以授权状态阻塞结构、写稿与生产；来源与授权状态仍登记。

## 4 默认值

| 项 | 默认值 |
|---|---|
| 时长 | 15 分钟（区间 8–20） |
| 画幅 / 帧率 | 16:9 / 1920×1080 / 24fps |
| 旁白语速 | **3.6 可见字/秒**（含停顿），只用于排镜头与 SRT |
| 旁白汉字数 | 时长 × 3.6（15 分钟约 3,240 字） |
| 节奏 | 句间 0.15–0.25 s；反转/证据处 0.8–1.2 s |
| SRT | `rules/shared/srt.md`；每条 ≤20 字、0 起点、估算时间轴、G1/G4 |
| 视觉 | 本线 `visual.md` 风格块 |
| 交付 | **正文视频 + 同基名 SRT**（都在单集）；不产配音、不混音、不烧录、不落库、不登记 |

## 5 门禁（两道）

- **门禁 A：剧本锁定**——通过 `script-workflow.md` 清晰度验收 + 本文件 §6 总字数预算 + 四栏改编提案（保留 / 重写 / 新增 / 反转）；锁定前跑 `lint_narration.py`。
- **门禁 B：正文成片**——剧情连贯、镜头稳定、时间线锁定；过门禁后只出 SRT 与交付。
- 像素级黑白屏/CFR/无音轨/无字幕流门禁按 `rules/shared/delivery.md` §四执行。
- 声线、配音、片头不再是门禁项。

## 6 开工前必须出的东西

1. **故事主线大纲**：按事件/情节点写，≥6 个节点；标出反转与每条物证的落点；不按段、不标时间、不拆字数；
2. **悬念预算表**：主悬念、次悬念、每个悬念的回收位置、结尾保留的 1–2 个未知；
3. **总字数预算**：目标时长 × 3.6 字/秒，只给总数，不拆段。

缺一不得进入写稿。

## 7 必须停的 9 种情况

1. 外部素材授权状态不明或未取得许可；
2. 素材涉及真实受害者、真实未成年人、真实在办案件；
3. 故事需要观众掌握超 3 条规则才能看懂；
4. 字数与目标时长偏差超过 ±20%，且用户不调整时长；
5. 关键物件的日常用途无法用一句话说清（违反 `script-workflow.md` 第二条）；
6. 医疗、法律、金融等专业细节无人核对；
7. 需要照搬某部已有影视/游戏的独特设定或镜头；
8. 平台审核风险（血腥、虐童、自杀细节）未与用户确认尺度；
9. 角色锚点未锁定就要开批量生图。

**硬停放行规则**：授权、医疗、法律、平台风险四类硬停，不因一句"继续/可以"而放行。放行必须逐项、具体、可记录。

## 8 我可以自行决定并记录的

- 分镜数量与切分位置（不改变故事事实）；
- 冷开场的具体首个画面（不改主悬念）；
- 证据物证的呈现顺序（回收位置不变）；
- 转场方式、镜头停留时长、SRT 断句。

## 9 交付与登记

- 终端交付 = **正文视频（MP4）+ 同基名 SRT**，都留单集：视频 `video/final/`，SRT `video/srt/`。
- 不产配音、不混音、不烧录、不落 `shared/delivery/`、不写成品卡、不登记。
- 发布侧（发布、平台登记）由用户手动完成，助手不参与。
