# 悬疑 · 单集输入契约（引入图片 + 正文视频 + 正文字幕）

> 2026-11-07 新建；2026-11-14 按「纯正文」口径收敛：删片头、配音、字幕烧录、成品库字段。
> 字段设计参考已归档的助眠线输入规则，具体字段按悬疑线重写。
> 收到新单时：先按 §0 走填写单，再按 §4 默认值开工。

## 0 使用方式

1. 复制 `shared/workflows/悬疑/EPISODE_INPUT_TEMPLATE.md`，另存为 `INPUT_<slug>.md`，放进单集目录。
2. 填 8 项必填（标题 / 母题 / 故事主线 / 主次悬念与反转 / 三条物证 / 结尾 / 来源与授权 / 目标时长）；4 项选填（必须覆盖 / 必须避免 / 参考材料 / 备注）。
3. 把文件路径发我，附一句"按 input-spec 执行"。

校验这 8 项；不合格只列问题清单，不上手写稿。通过后先出故事主线大纲、悬念预算表与总字数预算（§6），再进写稿。

## 1 三步

1. **定稿题材**：故事母题一句话，加"主悬念 / 次悬念 / 反转"三行。
2. **定来源**：原创、公版重构或外部素材；外部故事素材优先从知乎寻找，其他来源仅在知乎缺少合适且可核验候选或用户指定时使用，并写明来源与授权状态。
3. **定长度**：按故事节奏确定总时长，原则上不超过 25 分钟，不设 5 分钟最低要求，不为凑时长扩写。换算旁白汉字数见 `narrative.md`。超过 25 分钟的故事须压缩或改选，不通过拆集突破总时长上限。

## 2 必填（八项）

| 字段 | 说明 |
|---|---|
| 标题 | 4–40 字；不能写"待定 / 由你拟 / 无" |
| 故事母题 | 一句话，不超过 40 字；必须能直接复述"谁遇到什么异常、做了什么、付出什么代价" |
| 故事主线 | 按事件/情节点写，≥6 个节点；标出反转与每条物证落在哪个节点；不按段、不标时间、不拆字数 |
| 主悬念 / 次悬念 / 反转 | 三行；主悬念一个，次悬念最多一个；反转写清"哪条证据改写了前面哪个理解" |
| 三条可拍物证 | 每条 = 具体物件 + 在哪个节点出现 + 印证什么；至少一条要改写理解 |
| 结尾 | 停在哪个画面或哪句话；10 分钟以内的短篇优先留白，长篇优先写清因果并回收前文 |
| 来源与授权 | `原创` / `公版作品（写明依据）` / `受保护作品改编（作者、链接、许可状态）` / `公开事实复盘（来源链接与事实归因）` |
| 目标时长 | 按故事需要确定，原则上不超过 25 分钟；同时给出总汉字数（不拆段）。超过上限须压缩或改选 |

- **本线单独交付引入图片**：按 `delivery.md`，按当集确认分镜制作，不制作引入字幕；正文视频 0 秒即正文第一帧，没有标题卡、账号卡。
- 选填四项（填写单第 9–12 行）：必须覆盖 / 必须避免 / 参考材料 / 备注。

## 3 授权状态

- `original`：原创，无外部权利问题。
- `public-domain`：公版母题，须从公版原文重新原创。
- `authorization-pending`：受保护作品已选定但未取得改编许可——只能做改编提案与结构，不得写锁定稿、不得进生产。公开事实复盘使用 `public-facts`，按 `script-workflow.md` §7.2 做来源核验，不要求为公开事实取得授权。
- `authorized`：已取得书面许可，附许可范围。

**2026-11-09 用户接管授权**：用户明确"授权的事我会搞好"；助手不再以授权状态阻塞结构、写稿与生产；来源与授权状态仍登记。

## 4 默认值

| 项 | 默认值 |
|---|---|
| 时长 | 按故事实际需要确定，原则上不超过 25 分钟；不设最低时长 |
| 画幅 / 帧率 | 16:9 / 1920×1080 / 24fps |
| 旁白语速 | **3.6 可见字/秒**（含停顿），只用于排镜头与 SRT |
| 旁白汉字数 | 时长 × 3.6（5 分钟约 1,080 字；15 分钟约 3,240 字；25 分钟约 5,400 字） |
| 节奏 | 句间 0.15–0.25 s；反转/证据处 0.8–1.2 s |
| SRT | `rules/shared/srt.md`；每条 ≤20 字、0 起点、估算时间轴、G1/G4 |
| 视觉 | 本线 `visual.md` 风格块 |
| 交付 | **引入图片 + 正文视频 + 正文同基名 SRT**；引入不制作字幕，详见 `delivery.md` |

## 5 门禁（两道）

- **门禁 A：剧本锁定**——通过 `script-workflow.md` 清晰度验收 + 本文件 §6 总字数预算 + 四栏改编提案（保留 / 重写 / 新增 / 反转）；锁定前跑 `lint_narration.py`。
- **门禁 B：正文成片**——剧情连贯、镜头稳定、时间线锁定；引入图片另按 `delivery.md` 验收，过门禁后出正文 SRT 与三类交付物。
- 像素级黑白屏/CFR/无音轨/无字幕流门禁按 `rules/shared/delivery.md` §四执行。
- 声线、配音和引入视频不属于交付项；引入图片须按已确认方案验收。

## 6 开工前必须出的东西

1. **故事主线大纲**：按事件/情节点写，≥6 个节点；标出反转与每条物证的落点；不按段、不标时间、不拆字数；
2. **悬念预算表**：主悬念、次悬念、每个悬念的回收位置；短篇可规划留白，长篇列出主要因果与结尾回收位置。若故事代价落在人际关系上，可补一个由具体行动或物件承载的关系落点；不要求煽情或温情，也不作为必过项；
3. **总字数预算**：目标时长 × 3.6 字/秒，只给总数，不拆段。

缺一不得进入写稿。

## 7 必须停的 9 种情况

1. 使用受保护作品改编且许可未取得；或拟直接使用的图片、视频、音乐等素材权利状态不明；
2. 真实受害者、未成年人或在办案件的内容无法满足 `script-workflow.md` §7.3 的隐私、归因和非代入要求；
3. 故事需要观众掌握超 3 条规则才能看懂；
4. 字数与目标时长偏差超过 ±20%，且用户不调整时长；
5. 关键物件的日常用途无法用一句话说清（违反 `script-workflow.md` 第二条）；
6. 医疗、法律、金融等专业细节无人核对；
7. 需要照搬某部已有影视/游戏的独特设定或镜头；
8. 平台审核风险（血腥、虐童、自杀细节）未与用户确认尺度；
9. 角色锚点未锁定就要开批量生图。

**硬停放行规则**：许可、医疗、法律、平台风险四类硬停，不因一句"继续/可以"而放行。公开事实复盘不属于受保护作品改编许可门禁；来源不足时只停受影响的事实点，其他有来源内容和可独立推进的工作继续。

## 8 我可以自行决定并记录的

- 分镜数量与切分位置（不改变故事事实）；
- 冷开场的具体首个画面（不改主悬念）；
- 证据物证的呈现顺序（回收位置不变）；
- 转场方式、镜头停留时长、SRT 断句。

## 9 交付与登记

- 终端交付 = **引入图片 + 正文视频（MP4）+ 正文同基名 SRT**；引入图片在 `image/intro/vN/`，正文 MP4 与 SRT 同放 `video/final/`。引入不做字幕，详见 `delivery.md`。
- 不产配音、不混音、不烧录、不落 `shared/delivery/`、不写成品卡、不登记。
- 发布侧（发布、平台登记）由用户手动完成，助手不参与。
