# 人生体验线静帧生产规程 v1.2

> 2026-11-15 当前执行：状态、构图、光源数量、固定尺度/色彩数值及配比属于提示词指导和诊断，不作为审美停机/逐镜PASS门禁；以下旧阈值或清单若仍含硬性措辞，以本条为准。保留身份、关键剧情事实、文件引用与最终技术检查。局部编辑既有图可沿用源图，不强制从零重做两遍。


> 生效日期：2026-11-15。适用于本线每一集静帧生产、重开生产与生成器替换。
> 目的：把 `style.md` v3.7、`character.md` v7、`color-script.md` v1.4 和镜头/角色字段规则落实到实际资产、提示词、生成阶段和验收证据。

## 0. 规则入口与版本

开始分镜构建或生图前，必须逐一读取并在本集运行记录写下标题原文：

1. `rules/人生体验/README.md`
2. `rules/人生体验/style.md`（当前 v3.7）与 `rules/shared/visual-state.md`
3. `rules/人生体验/character.md`
4. `rules/人生体验/color-script.md`
5. `rules/shared/shot-composition.md`
6. `rules/shared/script-workflow.md` §15、§15.1
7. `rules/shared/video-workflow.md` §2.B、§2.C、§4
8. `shared/image-api/channel-policy.json` 当前 active 策略

- 以规则文件当前标题版本和正文版本记录为依据，不以旧集 `PROJECT_STATE`、旧脚本注释、旧 README 摘录或模型记忆代替。
- 标题版本与版本记录冲突时，记录两者原文；按最新版本记录执行。若正文互相冲突或无法确定有效条款，暂停生产并先解决冲突。
- 线路 README 的静帧实现入口是本文件；具体生成脚本可以换代，但必须通过本规程全部预检，不能因脚本名含 `v1/v2/v3` 就推定合规。

## 1. G0：剧本、角色和场地数据预检

- 按共享 `visual-state.md` 将人物/环境状态、时间原因与保留项写入已有事实卡及prompt；复杂连续性可另建状态计划，不强制新增文件。
- 每镜必须有 `shot_type`、`scene_id`、`has_character`、`fact`、`cast`、`closeup_part`、`view_angle`；字段枚举遵守 `script-workflow.md` §15 / §15.1。
- `cast` 表达旁白与画面事实，不是配比调节旋钮。旁白明确出现的人、丧尸或群体必须保留在场；不得为了打断连续人物镜头而把 `cast` 改成 `none`。
- 配比、连续人物镜或进场三连不合格时，调整镜头类别、增加有事实职责的建立镜或拆分序列；不得删除 cue 中必要人物。`cast=none` 但 cue / fact 要求可见人物时必须 FAIL。
- `visual` 中人物数量、动作、方向和场景事实必须与 cue、fact、cast 一致。无人环境镜不得在 visual 或 prompt 里留下角色标签、配角身份或人物动作。
- `image/color-plan.json` 必须包含每个实际场地的 `locations` 锚点；生成器读取该字段，不得只在另一份脚本中硬编码锚点。当前常用锚点：出租屋（502 门牌/入口识别、折叠桌、铁架床、掉皮墙角）；走廊（防火门、应急灯）；便利店（歪招牌、货架、收银台）；铁门（双开结构、焊缝、新锁）。单集未使用的场地标 `N/A`，不得静默删除已使用场地的锚点。

## 2. G1：角色参考资产预检

- 主角脸/表情镜使用 `assets/人生体验/characters/catman-20261113/character-reference/face-style-D.png` 与所需单档表情；全身比例使用同目录 `turnaround.png`。
- 站姿或全身镜必须附正式包 `turnaround.png` 中对应的正面、侧面或背面角度（猫爪、赤脚、平涂）。单张 API 限制时先做分区清晰的合成参考，并记录每个分区的源文件和用途。
- 猫爪特写必须附获批的猫爪参考。手脚要求仍按 `character.md`：三趾线、肉垫、赤脚、无人手指、无鞋、无尾。
- 配角按角色型别使用 `ref-helper-a.png`、`ref-helper-b.png`、`ref-helper-c.png`。`ref-chen.png`、`cat-face-crop.png` 等旧名不得回退使用；缺少对应新参考时停止该镜并补齐资产。
- 任何在场角色都必须有对应参考；多人镜需同时提供每个在场角色的参考。合成参考不得只留下猫脸、环境底图或其中一名角色。
- 开始生图前，检查所有引用路径存在、尺寸可读、对应当前规则版本；缺失或不匹配即 FAIL。

## 3. G2：提示词编译检查

- 状态描述应实际进入最终prompt：底图含场地状态，人物合成含人物状态和须保留的场地状态；身份参考不锁定洁净程度。sidecar保存计划版本/ID及实际解析数据。
每镜 prompt 由当前规则组件组装，不能只把部分句子复制进脚本：

1. `style.md` §四风格块；
2. 本镜事实卡与完整构图字段；
3. `color-plan.json` 中本章五色板、光线、环境色和唯一 accent；
4. `character.md` 对应角色、全身/角度、表情和爪部约束；
5. 道具归属、底部安全区、无文字等负向约束。

必须逐镜检查以下要点已真实进入最终发送的 prompt：

- 人物与道具平涂、2–3 个硬边色调、统一线宽；环境可使用渐变、AO、材质、可见光源、接触阴影和投影。
- `style.md` §2.1 四条负向：不许空墙+人；不得没有可见光源；不许纯平背景；不许整幅只有两个色块。
- 不得出现已废止的物件数量/材质数量/单镜色相配额（如“12–20 件”“三色相”“两种材质”）。
- 无人镜只写场景和无人约束，不拼接配角、圆头人、丧尸、角色身份等角色块；旁白事实若要求出现人，该镜就不能是无人镜。
- 构图写明镜头距离/机位/焦段、唯一明确的左或右站位、具体前景位置和场景锚点。不得使用“左或右”“某处”“压住边缘”等未决表述。
- M 镜按 `shot-composition.md` 落实人物与环境关系及人物尺度。提示词给出同深度门或家具的可信尺度关系，考虑透视和遮挡，不按固定像素比返工。
- 人物镜 prompt 必须明确猫头与身体共用线稿/平涂规则；只改变该镜指定表情，不重新设计身体、服装或角色身份。
- 人物镜也必须传本章完整色板；只传单一环境辅色或仅在无人底图阶段传色板不合格。

无人镜的环境 prompt 可以包含通用画风对人物/道具的说明，但必须用明确无人约束覆盖；不得包含任何角色专用描述。以最终发送给 API 的字符串检查，不以模板文件“看起来有”代替。

## 4. G3：生成阶段与可追溯记录

- `cast=none` 且事实卡确认无人：一遍生成环境成图。
- `cast` 含任一角色：第一遍生成无人环境底图；第二遍必须同时收到该环境底图和全部对应角色参考，再合成为单幅画面。环境底图保存于本集版本化目录（如 `image/env-v4/`），不能被其他轮次覆盖。
- 每次 API 调用按当前 `channel-policy.json` 路由，不硬编码通道、并发数或旧策略。重试与回退遵守该策略并记入记录。
- 每镜 sidecar 必须保存：最终完整 prompt 原文、prompt 版本/hash、`cue/visual/fact/cast/shot_type/scene_id`、所有参考图及用途、环境图路径、合成参考路径、阶段、channel/model/endpoint、并发队列标识、请求结果、尺寸、QA 状态。
- 仅 API 成功、图片存在或尺寸正确只代表技术生成成功，不代表规则验收通过。

## 5. G4：小样门禁与分批验收

- 按共享 `visual-state.md` 优化状态和群体提示词；样张用于确定用户希望的强度，不增加独立状态门禁、逐镜PASS表或审批环节。
- 首批小样不少于 6 镜，覆盖 E/M/C、无人/主角/配角或丧尸、室内/室外、日/夜、不同章色板；若某类别在小样缺失，补样后再判断。
- 先审最终 prompt 和参考图，再看原尺寸画面。人物镜必须 1:1 检查猫脸、头身比例、猫爪/赤脚、服装、平涂边缘和跨镜一致性；联系表不能代替原尺寸检查。
- 逐镜检查可见光源与投影、环境材质/明暗层次、四条负向、去人读图、场地锚点、人物尺度、旁白事实是否可见。
- 运行 `qa/audit_color_v3.py --src <本批输出目录>`，验收全片及章级色相、R/B、亮度、饱和度、尺寸。审计用于发现偏色，工具或字段缺失如实记录，不单因此阻断生成；不伪称完整审计已执行。
- 身份、关键剧情事实或技术错误优先修正受影响镜头；细小美术差异用提示词优化，不自动重抽或阻塞其他镜头。
- 正式图可按每24镜组织生成/查看/记录；局部美术修正可与后续生成交错。共性身份/剧情错误先修提示词再继续受影响镜头，不让单张小瑕疵阻塞整批。

## 6. 停机条件

以下任一情况立即停止相关镜头或整批，不得以“模型会自己处理”继续：规则版本冲突；必要字段或参考缺失；cue 与 cast 冲突；角色镜缺全身/配角参考；最终 prompt 未保存；分层阶段缺失；环境图被覆盖；必要的身份/剧情共性错误尚未解决。单独的美术建议或色彩诊断偏离不作为停机条件。
