# 旧文件主动清理规则

## 原则

- 维护工作区时主动识别并清理已失效、被替代、重复或不再引用的旧文件，不等待用户逐个点名。
- 清理目标是减少噪声与占用，同时保留仍能解释当前决策、复现流程或恢复正式资产的最小记录。
- 文件年龄、名称含 `old`/`archive`/`v1`、位于历史目录，单独都不足以判定可删。

## 清理前检查

1. 先确认当前规则、生成物和依赖引用，识别唯一真源、最新有效版本及可恢复副本。
2. 将拟清理路径、原因、体积和保留依据写入清单。
3. 执行删除前，先提交一轮 Git checkpoint；提交只包含本次已审阅的治理/清理变更，不夹带工作区其他未提交改动。无法安全拆分时，先停止删除并整理提交范围。
4. 逐项删除，记录删除文件数、释放空间和校验结果；清理不覆盖或降级生产资产。

## 默认删除对象

- 编译缓存、`__pycache__`、`.pyc`、临时日志、一次性调试脚本、失败请求残片。
- 已被新结果完全替代的重复渲染、中间预览、重复下载和无引用临时输出。
- 退役流程产生且无复用价值的 build 输出；保留必要的 QA 摘要和可复现信息。

## 必须保留或先确认恢复依据

- 当前规则真源、生产代码、正式交付、唯一参考资产、manifest/sidecar、重要 QA 与决策证据。
- 仅因处于 archive/旧版本目录而无法证明已替代的文件。
- 已完成项目中仍有用户明确要求保留的成品或素材。

遇到唯一性、依赖关系或用户保留意图不明确时，先停该项并报告，不扩大删除范围。

## GitHub

- 清理前的 checkpoint 与最终整理提交默认只提交到本地 Git。
- 未收到明确发布/推送指令，不推送 GitHub，也不修改远端分支。
