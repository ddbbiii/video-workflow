# 剧本编排最高规则 v2.8

> 生效日期：2026-11-18（v2.8；替代 v2.7）
> 适用范围：所有线路（助眠、悬疑、人生体验），所有新剧本与重新打开审核的旧剧本
> 核心目标：观众不需要行业知识、不需要规则说明书，也能复述人物为什么行动、异常怎样发生、结局留下什么未知
> 变更原因：v1.3 是双账号动画线时期的产物，混入旧 Story Package 字段、旧编号与旧验收表；本次改为线路无关，并把这一年实际踩过的坑（证据链、字数预算、授权四态、反转可回看）写进规则

## 0 核心判据

一句话必须能说清：**谁、遇到什么、做了什么、付出什么代价。** 四项缺一，不锁稿。

## 1 时代与可理解性审计

外部故事、旧故事、传统母题、用户提供的旧稿，推荐或改编前分别判断：

1. 原作距今多久，故事内部发生在哪个年代；
2. 关键物件、职业、机构、通信方式、出行方式、监控条件、求助流程，今天的目标观众是否仍能自然理解；
3. 旧逻辑放现代是否失效——人物明明可以用手机、监控、导航、报警或网络查询，却无理由不用；
4. 现代化是否会破坏故事核心。能自然更新则更新，适合保留年代则明确建立年代，两者都不成立则不推荐。

"旧"按理解成本与逻辑漏洞判断，不只看发表年份。**不得把年代混杂造成的疑问伪装成悬念。**

## 2 关键物件与行为

- 首次承担剧情作用前，必须用一句旁白或一个清楚画面说清：它是什么、为什么出现在这里、人物为什么此刻会用；
- 自制、改装或异常专用物件，必须区分"原本的日常用途"与"发现异常后临时增加的标记、测量或防护"；
- 物件价值不足以支撑人物继续处理它时，重写动机，不许补一句"他很好奇"。

## 3 简单悬疑优先

- 一个主悬念，至多再加一个次悬念；
- 观众需要理解的超自然规则**不超过 3 条**，每条必须能被一个画面或一个动作单独证明；
- 临时问题可以出现，但必须尽快回收；旧问题未解决时不得持续叠加新身份、新来源、新规则；
- 结尾最多留 1–2 个未回答问题；异常触发方式、人物关键选择、主要因果必须讲清；
- 为修漏洞而新增术语或子规则，若理解成本大于被修的问题，**回退简化，不打补丁**。

## 4 证据链（硬要求）

悬疑靠证据对上，不靠形容词堆气氛。

- 至少 **3 条可拍物证**，且能串成一条线；
- 每条都是具体物件：小票、录音、监控、病历、快递单、工单、照片、门禁记录、聊天记录；
- 证据之间互相印证，不是并列的氛围点缀；
- **至少一条证据在观众以为已经懂了之后，改写前面的理解**；
- 证据出现顺序 = 观众发现顺序；不做"旁白先总结、画面再演一遍"。

## 5 反转设计

- 反转必须**可回看**：至少 2 处前置伏笔，且伏笔落在画面上，不只在旁白里；
- 反转靠**重新解释已有信息**，不靠新信息空降；
- 不接受"其实一切都是梦/幻觉/精神病"作为唯一解释；
- 反转之后必须留 30–90 秒收尾，不允许反转完立刻黑场。

## 6 时长与字数预算

- 先定时长，再算字数，公式：**目标汉字数 = 目标时长（秒）× 线路语速（字/秒）**；
- 线路语速以各线路 `audio.md` 为准（助眠慢速、悬疑中速），本文件不写死数字；
- 写稿前出「分段字数表」，每段标：目标字数、累计时长、该段落地哪条证据；
- 写完核实际字数，偏差超过 ±20% 必须改结构或调时长，**不靠形容词和反复感慨凑数**。

## 7 外部来源、授权与事实复盘

先区分来源用途，分别记录来源链接、来源类型、具体支持的事实/表达、核验状态与使用方式。**受保护作品的改编许可、公开事实的来源核验、具体媒体素材的使用许可是三件不同的事，不得互相替代。**

### 7.1 受保护作品改编

- 小说、影视、游戏、非公版故事及其他受保护表达的改编，记录原作年代、故事设定年代、当代理解风险、需要重写的内容、故事复杂度和许可状态（`authorization-pending` / `authorized`）。
- 未取得改编许可时，只做结构层提案，不写完整改编旁白，也不使用其受保护的独特表达、角色、场景或视听素材。
- 公版作品须记录公版判断依据，并从原文独立重述；公版不代表可直接搬运现代译本、注释、插画或录音。

### 7.2 公开事实复盘

- 基于新闻报道、公开档案、研究或其他可追溯来源，对真实事件做原创措辞的事实综合/复盘，不属于对新闻作品表达的改编；无需为报道所载事实另行取得授权，也不要求必须找到官方原始通报才能开工。
- 官方或其他一手来源优先用于增强核验，但不是通用前置条件。建立事实矩阵，逐条关联来源和归因；关键事实尽量交叉核对。若当前只能找到一个来源，明确写成“据某来源报道/受访者称”；来源冲突时呈现差异或省略该点；没有来源支持的细节不补写。
- 以自己的结构和语言撰写，不大段照搬报道文字、独特表达或编排。新闻配图、视频、图表、音乐及其他具体素材仍各自受其权利状态约束，未获许可不得直接复用。
- “来源已记录”不等于“事实已核实”；反之，缺少官方材料也不意味着整期停止。将不确定内容限定到受影响的句子、镜头或段落，删去、归因或保守表述，并继续不受影响的工作。

### 7.3 真实人物、受害者、未成年人与案件

- 允许基于公开且可追溯资料进行克制的事实讲解；不得把旁白或虚构角色写成真实受害者本人，不得编造其对白、动机、内心、未公开经历、受伤与临终过程。
- 不把单一因素、救援人员推测或媒体判断写成调查结论；不公开与理解事件无关的私人身份信息，不呈现无必要的血腥或创伤细节。
- 涉及未成年人或在办案件时，额外保护身份与隐私，区分已证实事实、指控和推测；必要时匿名、缩窄内容或暂缓受影响部分。不得用这些类别的一句笼统禁令阻断所有基于公开事实的非代入式讲解。
- 不提供会促成现实伤害的操作性方法。

## 8 清晰度验收

剧本进入完整旁白与分镜前，逐项检查：

1. **一句话复述**：不了解设定的人能一句话说清三问；
2. **无术语理解**：删掉内部规则名后，观众仍能通过画面理解异常；
3. **四个为什么**：为什么是这个人、为什么是这个物件、为什么现在发生、为什么不采用更普通的处理方式；
4. **物件首次出现**：关键物件第一次承担剧情作用前，观众已知它的日常用途与出现理由；
5. **悬念预算表**：主悬念、次悬念、每个悬念的回收位置、结尾保留的未知；
6. **复杂度反证**：若解释一条规则需要连续区分多个相似工具、阶段或例外，标出理解风险与可简化方案，交用户决定。

任一项不过，故事包保持 `review-required`，不得锁定、不得下放生产。

## 9 复杂镜头的视觉事实卡

包含多主体、异常物件、多阶段状态、精确空间关系，或需要跨镜保持连续的镜头，先写视觉事实卡：

- 关键主体及其数量或组成；
- 每个主体的外观、姿态、动作阶段与状态差异；
- 前后、左右、远近、接触、遮挡与朝向关系；
- 观众在这一画面必须看懂的剧情事实；
- 与前后镜头必须保持或必须变化的连续性条件；
- 容易画错的镜头专属禁止项。

简单镜头不强行扩写；单张画面信息过载时拆分画面状态，不靠堆提示词硬塞。

## 12 旁白与画面提示必须分栏（2026-11-11 事故后新增，硬规则）

**事故**：`人生体验 No.001` 的 S41 写成「时间蒙太奇：凉席、电热毯…」、S59 写成「镜头拉远：窗帘还拉着…」。这两句是导演提示，却被当成旁白行：TTS 念了、字幕也压了，G1/G7 全过（因为锁定稿本身就是错的）。成片里观众听到「时间蒙太奇，凉席、电热毯……」。

**规则**：

1. **`cue` 只写观众要听到的话**。镜头、画面、转场、素材、后期提示写进独立字段（`visual` / `note` / `shot_note`），绝不进 `cue`、绝不进字幕。
2. **禁用词（命中即拦）**：蒙太奇、镜头、画面、空镜、特写、远景/近景/中景/全景、静帧、分屏、四格、拼图、转场、淡入、淡出、切至、画外音、旁白、字幕、配音、口播、录音、音效、配乐、垫乐、BGM、调色、画幅、构图、打光、第一帧、最后一帧、卡点、闪回、素材。括号里写画面提示同样拦。
3. **两个时点必须跑 lint**：`python shared/workflows/script-qa/lint_narration.py`——
   - 剧本锁定前：`script.md`；
   - 出 SRT 前：`shots.json` + `timeline.json`。退出码非 0 一律阻断。
4. **审查口径**：G1「cue == 锁定稿」不再等于合格——锁定稿本身要先过 lint，再按 SRT 的 G1「全部 cue 去标点按序拼接 == 锁定正文」判。
5. 用户原话里确实带这些词（比如引用片名）必须显式标注 `# user-literal` 并在 lint 里豁免，不允许默默放行。

## 13 线路适配


- 本文件只写通用底线，不写具体题材结构、镜头语法、画风；
- 结构模板、时长、语速由各线路 `narrative.md` / `audio.md` 定义；
- 线路可以比本文件更严，**不得更松**；放宽必须由用户明确批准并记录。

## 14 故事包最低字段

各线路可自行定义格式，但最低必须包含：来源类型与权利状态、来源清单、与题材相称的事实/证据矩阵及复杂度结论。受保护作品改编另含三问、悬念预算表和许可状态；公开事实复盘另含事件时间线、关键主张的来源归因与未确认项，不强制套用虚构故事的悬念、反转或授权字段。

## 15 镜头类型、场地与 fact 字段（2026-11-14 新增，11-15 加 fact）

- 悬疑线、人生体验线：每个镜头除 `cue` 与 `visual` 外，必须再标三个字段：

  ```text
  shot_type：E | M | C
  scene_id：<场地 ID>（如 502 / corridor / lobby / store / street / gate）
  fact：<这一镜观众必须看懂的一件事>，一句话，≤40 字
  ```

- 定义与配比真源：`shot-composition.md`（E 22% / M 53% / C 25%，±3pp；进场先 E1+E2；连续 6 镜内至少 1 个 E；连续含人物镜 ≤5）。
- `fact` 写可验证的事实（他在做什么、画面多了什么、空间哪里不对），不写"氛围/过渡/情绪"；**空 fact 不许进批量**，填不出就删镜或并镜；同一场次内不许重复（2026-11-15 新增，起因：悬疑 8 镜小批 B2 空手背影镜，`fact` 为空且与 A1/B1 重复）。
- 剧本锁定前跑 `shared/workflows/body-only/check_shot_mix.py --script <script.md>`，退出码非 0 不得锁稿；悬疑线加 `--require-fact`（空 fact 直接 FAIL），人生体验线暂以 NOTE 提示。
- 这里的字段描述**镜头类型、场地与信息职责**，不写画面提示；画面内容仍写在 `visual`，旁白仍只写 `cue`（§12 不变）。

### 15.1 在场人物、特写部位与角度（2026-11-14 新增，硬字段）

起因：EP03 v3 有 16 镜把「两人…」写成散文，生成器靠正则猜在场人物，漏判后整镜没发主角参考，猫被画成灰白猫。
**人物在场关系不得只写在 `visual` 的中文里**，必须另有固定枚举字段；生成器与门禁只认字段，不再猜散文。

每镜追加三个字段：

```text
cast：catman | chen | catman+chen | none | body-only
closeup_part：face | hand | paw | prop | none
view_angle：front | three-quarter | side | back
```

- `cast`：角色 ID（主角 `catman`、配角 `chen`），多人用 `+`；`none`＝画面无人，`body-only`＝只出现局部（手/爪/腿/背影），局部属于谁写在 `closeup_part` 与 `visual` 里。
- `cast` 必须忠实表达 cue、fact 与 visual 的在场关系；不得为了镜头配比或打断连续人物镜而将必要人物改成 `none`。遇到连续人物镜门禁冲突，先调整镜头类别或序列，保留原有剧情事实。
- `closeup_part`：本镜主要特写对象。`hand` 必发人手参考、`paw` 必发猫爪参考，只靠文字描述不算。
- `view_angle`：脸的主角度。`side` / `back` 不允许做脸部情绪特写（见 `rules/人生体验/character.md` §4.2）。
- 门禁：`shared/workflows/body-only/check_cast.py --script <script.md> --refs <refs 目录>`。
  以下任一即 FAIL：① `cast` 里某角色没有参考图；② `cast` 与 `visual` 出现的人名/部位不一致；③ 缺字段。
- 回填与生成器约定：所有逐镜生产实现一律从这三个字段取主体与参考图，禁止再用中文正则猜角色；生成后必须核对 cue/fact 与 cast 的事实一致性。

## 16 旁白语言清晰度

- **旁白必须自然、直白、首听即懂。** 先写清人物、动作、物件和变化，再考虑修辞；不能让观众停下来解码句子。
- **代入感是叙事目标，不是固定格式。** 根据题材选择第一人称、第二人称、第三人称或贴近人物的有限视角；在适合的段落里，让观众跟随人物当时能看见、听见、知道和选择的内容经历事件，不机械统一全篇人称。
- 具体动作、物件、身体感受和感官细节都可以帮助观众进入处境，但不是每集必备清单。只有在能呈现行动、判断变化或实际代价时才使用，不为凑篇幅堆动作、寒冷、疼痛或情绪描写。
- 真实事件中的感官、心理和个人经历不得无依据地写成当事人事实；遵守 §7.3。戏剧化重构须与可核实事实区分，并按项目口径标注，不得伪装成当事人口述。
- 能用自然口语准确直说时，不用抽象比喻或诗性表达替代关键信息。避免把概念硬写成动作/物件、用意象代替可见变化，或使用不符合中文习惯的动宾搭配。
- 比喻可以保留，但须同时满足：意思能从上下文立即听懂；不遮蔽人物做了什么、发生了什么；符合当前人物视角与语气。否则改成具体陈述。
- **朗读复核：** 锁稿前逐段朗读，逐句检查第一次听能否立即明白“谁在做什么、发生了什么变化”。凡需要回读、脑内翻译、补主语或猜比喻的句子，必须改写。不能以“有氛围”或“有文采”作为保留理由。
- 典型问题与改法：
  - “背包里没有装进今晚” → “背包里没有帐篷、睡袋等过夜装备。”
  - “雾落下来后，路在缩短” → “雾越来越浓，只能看清前面几步。”
  - “少了一条向山下说话的通道” → “手机不能用来联系山下。”
