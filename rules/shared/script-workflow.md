# 剧本编排最高规则 v1.3

> 生效日期：2026-07-28  
> 适用范围：所有账号、所有新剧本、所有重新打开审核的旧剧本  
> 规则所有者：`剧本编排｜双账号`  
> 核心目标：制作简单易懂的悬疑故事。观众不需要行业知识或规则说明书，也能复述人物为什么行动、异常怎样发生以及结局留下什么未知。
> 运行边界：本文件只由剧本编排会话维护和执行；生产会话不订阅、不审核本规则，只接收用户确认后的具体锁定故事包。

## 一、获取剧本前先做时代可理解性审计

外部故事、旧故事、传统母题和用户提供的历史稿，在推荐或改编前必须分别判断：

1. 原作或母题距今多久；故事内部发生在哪个年代。
2. 关键物件、职业、机构、通信方式、出行方式、监控条件、求助流程和社会习惯，今天的目标观众是否仍能自然理解。
3. 旧逻辑放到现代是否失效，例如人物明明可以使用手机、监控、导航、报警或网络查询，却无理由不用。
4. 现代化改编是否会破坏故事核心。能自然更新则更新；适合保留年代则明确建立年代；两者都不成立则不推荐该故事。

“旧”不是仅按发表年份判断，而是按理解成本和现实逻辑判断。不得把年代混杂造成的疑问伪装成悬念。

## 二、关键物件和行为必须自然进入故事

任何对剧情有关键作用、但普通观众未必熟悉的物件、装置、职业流程、场所功能或人物行为，在第一次关键使用前必须完成最短说明：

- 它是什么；
- 为什么会出现在这里；
- 人物为什么此刻会使用它。

默认用“一句旁白或一个清楚画面”完成，不写百科说明。普通生活物件不需要重复解释。

自制、改装或异常专用物件必须区分：

1. 原本的日常用途；
2. 人物发现异常后临时增加的标记、测量或防护措施。

不得让一个日常场景一开始就自然拥有只为本集异常量身定做的复杂设备。若物件的经济价值、情感价值或业务价值不足以支撑人物继续处理它，必须重写动机，不能只补一句“他很好奇”。

## 三、简单悬疑优先于规则严密

- 每集只保留一个主要悬念，可以再有一个次要悬念。
- 临时问题可以出现，但必须尽快回收；不得在旧问题未解决时持续叠加新的身份、来源、规则和幕后谜团。
- 结尾最多留下一个至两个未回答问题。异常触发方式、人物关键选择和主要因果必须让观众看懂；可以保留异常来源或人物后续命运，不要两者之外再留下多层谜团。
- 面向观众的超自然规则应尽可能压缩，三条以内是默认简洁目标而不是硬性上限；每条都必须能通过画面或行动单独证明。确有必要超过时，先说明新增规则的必要性与理解成本，再由用户决定是否保留。
- 核心操作物件不设数量上限。复杂、陌生或容易混淆的物件必须在首次关键使用前做简短说明，并控制全部说明占用的篇幅。
- 当物件较多导致前置解释挤占剧情、多个物件功能难以区分，或观众必须记住操作手册才能理解时，剧本编排会话必须直接指出问题、给出简化建议并询问用户，不得自行把数量上限当成否决理由，也不得不提醒就继续锁稿。
- 为修复漏洞而新增术语、装置或子规则，如果带来的理解成本大于被修复的问题，必须回退并简化故事，而不是继续打补丁。

## 四、清晰度验收

剧本进入完整旁白和分镜前，必须通过以下检查：

1. **一句话复述**：不了解设定的人能用一句话说清人物遇到了什么、做了什么、付出了什么。
2. **无术语理解**：删除内部规则名后，观众仍能通过画面理解异常。
3. **四个为什么**：为什么是这个人、为什么是这个物件、为什么现在发生、为什么不采用更普通的处理方式。
4. **物件首次出现**：关键物件第一次承担剧情作用前，观众已经知道其日常用途和出现理由。
5. **悬念预算**：明确列出主悬念、可选次悬念、每个悬念的回收位置，以及结尾保留的未知。
6. **复杂度反证**：若解释一条规则需要连续区分多个相似工具、角度、阶段或例外，必须标出理解风险、预计解释篇幅和可简化方案，交由用户决定；确认前保持 `review-required`。

任何一项不能通过，故事包保持 `review-required`，不得锁定或下放生产。

## 五、获取外部故事时的交付要求

推荐或取得一个外部剧本时，候选摘要必须增加：

- 来源与授权状态；
- 原作年代和故事设定年代；
- 当代观众理解风险；
- 需要现代化或补充说明的物件与行为；
- 主悬念、次悬念和预计结尾留白；
- 面向观众的规则数量、关键道具数量及其预计解释篇幅；数量只用于评估理解负担，不作为硬性淘汰标准；
- `直接可用 / 简化后可用 / 不建议采用` 的结论。

不得只因为故事热门、反转强或设定新奇就进入编排。

## 六、Story Package 必填字段

今后所有新版本 story package 必须包含：

1. `时代与当代可理解性审计`；
2. `关键物件/行为首次出现说明表`；
3. `悬念预算与回收表`；
4. `观众规则卡`，只写观众必须理解的规则；数量不设硬上限，但必须标出超过默认简洁目标时的必要性；
5. `一句话复述测试`；
6. `复杂度结论：通过 / 建议简化并待用户决定 / 用户确认保留当前复杂度`。

## 七、复杂镜头必须具备可执行的视觉事实

复杂画面不能只写氛围、情绪或概括性动作。凡是包含多个主体、异常物件、多阶段状态变化、精确空间关系、可见与不可见差异，或需要跨镜保持连续性的镜头，必须先建立可供后续画面提示词直接使用的视觉事实卡。

视觉事实卡按实际需要写清：

- 画面中的关键主体及其数量或组成；
- 每个主体当下的外观、姿态、动作阶段和状态差异；
- 人物、物件、环境之间的前后、左右、远近、接触、遮挡与朝向关系；
- 观众在这一画面必须看懂的剧情事实；
- 与前后镜头必须保持不变或必须发生变化的连续性条件；
- 容易被模型误解、补全或画错的镜头专属禁止项。

提示词复杂度由画面事实复杂度决定，不追求无意义的长提示词。简单镜头不强行扩写；复杂镜头不得为了省字把关键数量、状态和空间关系交给模型猜测。若单张画面承载的信息过多，即使增加提示词仍难以稳定表达，应拆分画面状态或调整分镜，而不是继续堆叠描述。

剧本阶段不直接进行图片生产，但 shot-beat 表中的复杂镜头必须达到能够编译成上述提示词的清晰度。

与生产域对齐（2026-09-17）：**完整静态分镜不再作为进入后续视觉/音频生产的强制人工门禁**——生产侧以 `video-workflow.md` 为准（静态自动生成、不拦主流程；用户主动要求时才出联系表复核）。剧本域仍须保证复杂镜头的视觉事实卡与清晰度验收通过后，故事包才能锁定下放；不得把「静态分镜人审」写成生产硬门禁。

现有已锁定故事包不会仅因本规则发布而自动失效；一旦重新打开剧情审核或创建新版本，必须按本规则补齐审计。
