# 视频制作固定工作流（用户确认版 v1）

> 变更：2026-09-17 动态默认改为 H3 关键 / Wan 微动 / LTX 特殊，E 明确草稿登记与接缝并审，三道人工门禁不取消；2026-10-06 静态生图默认独立 GPT 图片 API，关键旁白事实必须可见；2026-10-18 镜头/素材降级回退不得静默执行（newton-to-chaos 12 镜静默回退事故）。
> 细化：封面片头见 `visual/cover-and-intro.md`，声线字幕见 `audio/voice-and-subtitles.md`，交付见 `delivery/final-delivery.md`。
> 状态：强制默认流程。任何跳过、倒置、插入未定义审核环节或错误阶段重写内容，主控必须先提示“偏离点”并等用户确认。

## 0 前提

- 先锁定剧本、世界规则、角色关系、镜头节拍与剧情揭示顺序。
- 剧本锁定后不重新分析、改写或扩写，除非用户明确要求修改文本。
- 每镜生成事实约束卡：人物身份/数量/位置、物件尺度与状态、地点、禁止项。它是生图与动态输入，不是人工审核项。
- 约束卡必须列出该段旁白中观众需看见的关键事实及表达方式，不能用主题相近的氛围图代替实验、变化、关系或因果；非关键背景不要求逐词配图。
- 单幅画面承载过多时，可在同一旁白段落内拆多个画面状态或使用可控图解与动作；默认保留已批准旁白与时序，不通过加速朗读或擅自改文案凑镜头。无法在现有时长内清楚表达时先提冲突。

## 1 固定执行顺序

剧本锁定 → 声线配置 → 静态分镜 → 动态关键镜头 →〔门禁 1：关键动态〕→ 正文视觉成片 →〔门禁 2：正文成片〕→ 片头文案 → 生成片头 →〔门禁 3：片头〕→ 拼接 → 配音/字幕/混音 → 最终交付。

## 2 各阶段规则

### A 剧本锁定

- 输入可为用户原稿、AI 原创、已授权改编或许可明确的素材。
- 输出须含完整旁白、逐镜节拍、角色表、地点/道具连续性、`foley_requirement`。
- 用户确认后进入生产；非用户要求不得在后续视觉阶段改剧情。

### B 角色与声线

- 自动列出叙述者、主角、配角与仅画面出现的人物；每个有可听台词的角色绑定 `voice_id`。
- 同一角色同集与跨集：同一声线锚点、clone prompt、`do_sample=false`、固定 seed；不得因分段生产换音色、换 seed、换模型或变速。
- 特殊场景（梦境、电话、情绪失控、广播失真）须有理由、适用镜头范围与回退规则。
- 无已批准声线时必须提示，不得暗中用随机新音色替代。

### C 静态分镜

- 不要求用户审核静态分镜。剧本与声线确定后自动生成所需静帧、场景母版、角色/道具参考与运行清单。
- 视觉基线沿用 UA004《停播节目》方向：破败调查漫画 + 成熟简洁赛璐璐人物，低饱和蓝灰、弱暖光、清晰线稿、无幼态化。
- 生图用事实约束卡与稳定风格模板，避免人物数量、性别、物件尺度、场景功能与画风漂移。
- 默认独立 GPT 图片 API，网格与独立图按 `image-grid-generation.md` 选择；付费调用遵循已确认预算，内置 Codex 生图与本地文生图不作为自动替代。
- 验收核对关键事实是否可见、是否误导，不只看好看或主题相似；精确数量/方向/科学关系无法稳定生图时优先确定性图层。
- 静态结果保存为可追溯资产，不拦主流程；仅用户要求时出联系表复核。

### D 动态关键镜头

- 按叙事价值筛选：状态变化、人物反应、恐怖揭示、空间建立、关键动作。
- 每镜只标一种主要动态方式：静态、推拉平移、微动、关键动作；不要求每镜进 I2V。
- 普通信息镜头保持静态或 2.5D 轻运动，不为“全片都动”增加不稳定。
- 只有关键动作使用起止状态图；普通推拉与微动不增加状态管理。
- 高风险物理动作（插拔、门锁、屏幕文字、手与道具接触）用起止状态图/遮罩/确定性过渡；I2V 只负责轻微运动，结束停在最后状态帧。
- **I2V 失败不得静默回退**：任何镜头/素材级降级或回退（I2V 退回静帧推拉、动态降静态、换镜头类别或素材、时长不足换备选、模型路由降档）必须先汇总清单——镜头 ID、原计划类别、实际替代、原因、影响时长——统一交用户审核，确认后继续；清单与结论记入运行日志。已在成片中发生的回退，必须在 G 门禁与 QA 报告显式披露。单镜返工成本不是跳过审核的理由；用户可批量放行，决定权在用户。
- 选型按 `shared/workflows/PRODUCTION-MOTION-ROUTING.md`：关键动态默认 MiniMax H3（EasyCache ON，16GB 短窗分片）；微动默认 Wan（EasyCache OFF，除目检后开启）；特殊物理/旧 LTX 镜用 LTX distilled。模型产出的原生环境声单独存 stem，不烘焙进正文。

### E 门禁 1：关键动态

- 用户只审核被选中的动态镜头成品（含 H3 分片接缝、身份与光影稳定性；不另设接缝门禁）。
- 未通过只重制指定镜头或其结构资产，不得无理由重跑整集静帧。
- 发布路径：通过后锁定版本与 hash，进入正文剪辑。
- 草稿路径：试动作可用未登记临时 first_frame；过门禁后执行 `register-approved-shot-keyframe`（或等价登记）写入 SHA-256 再进正文。日常不为加速 A/B 另开评测门禁；仅改默认参数或选型争议时目检。

### F 正文视觉成片

- 由通过的动态镜头、其余静帧、转场与镜头时长自动合成。
- 产出为**正文视觉成片**：不含片头、不烧字幕、不混最终配音；可保留独立环境声候选，不得烘焙 BGM。
- 记录镜头顺序、时长、源资产、转场与版本 manifest。

### G 门禁 2：正文视觉成片

- 用户审核剧情连贯、画面逻辑、动态稳定性、需重制的单元。
- 通过后正文时间线锁定；此后改镜头时长必须提醒会影响旁白与字幕对齐。

### H–J 门禁 3：片头文案与成片

- 用户先定片头钩子文案；默认含账号识别、集号、异常钩子、书名号标题。
- 用同集稳定声线生成片头视频；BGM 是否加入由用户明确决定。
- 片头单独交用户审核，通过后才允许接入正文。

### K–L 自动最终后期

- 自动拼接已批准片头与锁定正文。
- 再生成独立旁白、角色台词与其他获准音频素材；旁白、拟声、BGM 独立存 stem。默认交用户手动混音与 Subtitle Edit 字幕，分工以 `audio/manual-post-production.md` 为真源；自动混音/ASR 仅在用户明确委托时使用。
- BGM 可选：只有用户要求或已锁定规则要求才执行。启用前必须有明确风格来源（用户风格描述、参考曲目/氛围、已批准 BGM 资产 ID，或经确认的方案），不得随意生成。
- BGM 先出短循环候选试听，用户确认或授权主选后才全片循环/分段叠层；混音以旁白可懂为先，默认连续低存在感背景层；关键节点可叠氛围层，不频繁换歌、不抢旁白。
- BGM 返工只重混音轨或替换 stem，不重做画面/旁白/拟声/字幕；影响可读性或辨识度时优先调音量、淡入淡出、分段叠层或 sidechain ducking。
- 字幕在片头与正文时间线、最终旁白母带锁定后处理。先复用与母带版本匹配的词/字级时间轴；无可用时间轴或同步验收失败才跑本地 ASR。锁定显示文本映射为短句字幕后生成本地侧车文件并烧录发布派生版。
- 字幕默认半透明深色底条、白/暖白单行短句、居中、底部安全区；样式与画幅校准见 `audio/voice-and-subtitles.md`。字幕不得烘焙进 clean master。
- 不允许以 VAD 静音段、字符比例切分或整体偏移冒充词级同步。
- “精准字幕校对”是可选返工：仅在 ASR 依赖缺失、自动对齐失败或用户反馈不同步时，只重建 SRT 与烧录版，不重跑画面/旁白/拟声，除非用户明确要求。
- 默认最终输出只有完整无声无字幕视频与完整独立配音，起点与时长一致，见 `delivery/final-delivery.md`。字幕侧车与烧录版由用户手动后期或受托制作，不自动额外交付；返工只处理受影响产物。

### M 最终交付

- 按 `delivery/final-delivery.md` 核验两个交付文件：视频无音频/字幕流、配音与视频时长及同步；QA/manifest 存内部目录。
- 用户最终确认后才登记到 `C:\Users\10060\Desktop\douyin成品.md`。
- 不默认额外交付封面、字幕版、预览或文案；用户要求时单独处理。内部素材不因最终输出收敛而自动删除，清理须授权。

## 3 偏离处理

以下必须提醒并等用户确认：

1. 剧本锁定后改剧情、角色关系或旁白文本；
2. 跳过关键动态审核直接合成正文；
3. 未审核正文就做片头或进入最终配音/字幕；
4. 未审核片头就接入正文；
5. 最终配音后改正文时长却不重建音频/字幕；
6. 为提速换同角色声线、采样策略或 seed；
7. 擅自加用户未要求的 BGM、插帧或画质增强；
8. 启用 BGM 未先明确风格来源，或未保留可单独替换的 BGM stem；
9. 任何镜头/素材的静默降级或回退（见 §2.D）。

提醒格式：说明“会跳过/倒置哪项门禁、影响哪些已锁定产物、确认后如何执行”。未获确认不得继续。

## 4 当前默认技术

- 静态图：独立 GPT 图片 API 优先；已验证 `https://dklapi.com/v1/images/generations`、模型 `gpt-image-2.5-sunburst`、支持 2048×1152。密钥只从环境变量读取，不回显不落盘；带参考图须验证上传方式。变更模型或接口须先确认。
- 本地 ComfyUI 用于已批准的图生视频、结构控制、超分等辅助，不自动替代 GPT 生图；角色参考按线路已批准资产管理。
- 动态：关键 H3 I2V（8189，EasyCache ON，16GB 短窗分片约 5 s/段 + first_frame 接龙）；微动 Wan 2.2（EasyCache 默认关，开启须目检）；特殊物理/旧 LTX 镜用 LTX 2.3 distilled + ManualSigmas，Portable 常驻 `--disable-pinned-memory`。高风险精确几何仍用起止状态图/遮罩/FFmpeg；Hunyuan 仅实验。
- 声音：本机 Qwen3-TTS + 已批准声线资产；BGM 生成方案按当前许可与实测重新选型，旧 ACE-Step 流程退役。
- 字幕：本机 Faster-Whisper 或 FunASR 词/字级时间戳 + 锁定文本；中文长解说优先 FunASR。
- 合成：FFmpeg；插帧仅在用户终审后显式启用。

## 5 文档优先级

本文件是最高优先级流程说明。项目内 `docs/video-production-workflow-master-v1.md`、各集 `PROJECT_STATE` 与运行日志必须与之一致；冲突时以用户最新明确指令和本文件为准。

## 6 特殊场景与规则变更

- 单集/单镜/单次交付的特殊要求默认只是该项目局部覆盖，须写入 `PROJECT_STATE` 或运行日志。
- 局部覆盖不自动修改本文件的固定顺序、门禁、声线规则或技术默认。
- 只有用户明确说“写回工作流”“设为长期规则”“以后都按这个”，才允许更新本文件，并记录原因、影响范围与生效日期。

## 7 会话治理

- 会话职责与规则写权限见 `governance/session-governance.md`。
- 剧本编排会话拥有剧本域工作流修改权；两个生产会话无权改最高生产规则，变更须提交规则中转会话。
- 规则中转会话收到申请后必须先问：仅某账号、还是所有账号通用；未确认范围与内容前不得写入规则文件。
