# 视频制作固定工作流（纯正文版 v2）

> 2026-11-14 用户指令：**成品视频只包括完整的正文，不包含引入、标题、字幕、配音；只输出一个视频 + 对应的 SRT**。配音、混音、BGM、烧录、发布全部由用户手动。任何与本节冲突的旧规则、旧交接、旧脚本默认值一律作废。
> 交付真源：`delivery.md`；SRT 真源：`srt.md`。本文件管生产顺序与门禁。

> **仅悬疑线覆盖交付范围**：引入图片 + 正文视频 + 正文字幕；引入不做字幕、不拼入正文 MP4，见 `../悬疑/delivery.md`。以下正文流程和技术 QA 继续适用；其他线路交付范围不变。

> **2026-11-27 用户确认**：需要片头时，优先复用本机剪映组合预设。自动化只替换用户指定的图片/视频素材和文字，保留预设中的剪映原生特效、音效、嵌套结构和时间关系；配音由用户在剪映中手动生成和替换。片头完成后回到剪映新草稿继续编辑，最终视频导出仍由用户决定。

## 0 前提

- 先锁定剧本、世界规则、角色关系、镜头节拍与剧情揭示顺序。锁定后不重新分析、不改写，除非用户明确要求。
- **`cue` 只写观众要听到的话**：镜头、画面、转场、字幕、音效、BGM 等制作术语不得进旁白。锁定前必须跑 `python shared/workflows/script-qa/lint_narration.py <script.md> --json`，退出码非 0 不得锁定。
- 每镜生成事实约束卡：人物身份/数量/位置、物件尺度与状态、地点、禁止项。约束卡必须列出该段旁白中观众需看见的关键事实，不能用主题相近的氛围图代替实验、变化、关系或因果。
- 单幅画面承载过多时，可在同一旁白段落内拆多个画面状态或使用可控图解；默认保留已批准旁白与时序，不通过加速朗读或改文案凑镜头。无法在现有时长内表达清楚时先提冲突。
- **批量前预检**：批量生图前做 1 次试调用核对余额；最终编码前检查目标盘剩余空间 ≥2× 预计产物 + 10GB。任一项失败先停，不先跑一半。
- 本流程不生成任何音频，也不需要试音、声线或 BGM 预检。

## 1 固定执行顺序

剧本锁定 → 静态分镜 → 动态关键镜头 →〔门禁 1：关键动态〕→ 正文视觉成片 →〔门禁 2：正文成片〕→ SRT → 像素级 QA → 最后回写剪映草稿（按需）→ 交付（正文视频 + SRT）。

- **默认没有片头阶段，也没有门禁 3**。正文第一帧就是正文成片第一帧。只有用户明确启用片头时，才在最后回写剪映草稿阶段加入片头。
- **没有配音、混音、烧录、落库、成品卡、发布登记**。这些全部由用户手动，助手不代做、不提醒接力。
- 交付只有两件，都留在单集 `video/final/`：正文视频与同基名 SRT。SRT 是独立文件；MP4 仍无字幕流、无烧录字幕。路径、命名、技术规格见 `delivery.md`。

## 2 各阶段规则

### A 剧本锁定

- 输入可为用户原稿、AI 原创、已授权改编或许可明确的素材。
- 输出须含完整旁白、逐镜节拍、角色表、地点/道具连续性、`foley_requirement`（仅作文档字段，不产音频）。
- 旁白与画面提示必须分栏：`cue` 只写观众要听到的话；镜头/画面/转场/后期提示写进独立字段。
- 用户确认后进入生产；非用户要求不得在后续视觉阶段改剧情。

### B 角色与视觉资产

- 自动列出叙述者、主角、配角与仅画面出现的人物；需要跨镜一致的角色先立身份锚点（三视图/脸裁切/服装色块）。
- 同一角色同集与跨集：同一张脸、同一套服装色、同一比例；不得因分段生产换脸、换发型、换画风。
- 需要特殊状态（梦境、回忆、受伤、老化）时，写明适用镜头与回归点。
- 没有已批准角色资产时先建锚点，不得用随机形象开批量。

### C 静态分镜

- **叙事视觉状态**：开工必读 `visual-state.md`；将人物/环境状态、时间因果、表现强度和群体空间关系写入已有事实卡及底图/合成prompt；复杂时可另建状态表。画法简洁不等于衣物/场地洁净，不增加独立审美门禁。
- 不要求用户审核静态分镜。剧本锁定后自动生成所需静帧、场景母版、角色/道具参考与运行清单。
- 生图用事实约束卡与稳定风格模板，避免人物数量、性别、物件尺度、场景功能与画风漂移。
- **分层生成（2026-11-15）**：`cast=none` 的镜一遍出图（环境 rich、明确写"画面里没有人"）；`cast` 含角色的镜走两遍（先生成无人环境底图，再以「场景｜人物参考」拼图合成人物）；关键动作镜逐镜目检，必要时第三遍。无人镜提示词里不许出现配角描述，否则会凭空多出人。
- **批量节奏（2026-11-15）**：按约24镜组织生成、查看和记录，及时发现共性身份/剧情错误；局部美术修改可与后续生成交错，不因单张小瑕疵阻塞整批。
- 默认独立 GPT 图片 API，网格与独立图按 `image-grid-generation.md` 选择；内置 Codex 生图与本地文生图不作为自动替代。
- 验收核对关键事实是否可见、是否误导，不只看好看或主题相似；精确数量/方向/科学关系无法稳定生图时优先确定性图层。
- **画面内不得出现标题、章节卡、账号名、字幕、水印、logo**；所有文字层都不做。
- 静态结果保存为可追溯资产，不拦主流程；仅用户要求时出联系表复核。

### D 动态关键镜头

- 按叙事价值筛选：状态变化、人物反应、恐怖揭示、空间建立、关键动作。
- 每镜只标一种主要动态方式：静态、推拉平移、微动、关键动作；不要求每镜进 I2V。
- 普通信息镜头保持静态或 2.5D 轻运动，不为"全片都动"增加不稳定。
- 只有关键动作使用起止状态图；普通推拉与微动不增加状态管理。
- 高风险物理动作（插拔、门锁、屏幕文字、手与道具接触）用起止状态图/遮罩/确定性过渡；I2V 只负责轻微运动，结束停在最后状态帧。
- **I2V 失败不得静默回退**：任何镜头/素材级降级或回退（I2V 退回静帧推拉、动态降静态、换镜头类别或素材、时长不足换备选、模型路由降档）必须先汇总清单——镜头 ID、原计划类别、实际替代、原因、影响时长——统一交用户审核，确认后继续；清单与结论记入运行日志。已在成片中发生的回退，必须在 QA 报告显式披露。
- 选型按 `shared/workflows/PRODUCTION-MOTION-ROUTING.md`：关键动态默认 MiniMax H3（EasyCache ON，16GB 短窗分片）；微动默认 Wan（EasyCache OFF，除目检后开启）；特殊物理/旧 LTX 镜用 LTX distilled。模型产出的原生环境声单独丢弃或留在项目外，不烘焙进正文视频。

### E 门禁 1：关键动态

- 用户只审核被选中的动态镜头成品（含 H3 分片接缝、身份与光影稳定性；不另设接缝门禁）。
- 未通过只重制指定镜头或其结构资产，不得无理由重跑整集静帧。
- 发布路径：通过后锁定版本与 hash，进入正文剪辑。
- 草稿路径：试动作可用未登记临时 first_frame；过门禁后执行 `register-approved-shot-keyframe`（或等价登记）写入 SHA-256 再进正文。

### F 正文视觉成片

- 由通过的动态镜头、其余静帧、转场与镜头时长自动合成。
- 产出为**正文视觉成片**：不含任何片头、标题、章节卡、字幕、文字层、音轨、BGM。
- 2026-11-14 起没有配音可对时，镜头时长按估算语速排（助眠 3.8 字/秒、悬疑约 3.6、人生体验 4.8），并与 SRT 共用同一份 `timeline.json`/`cues.json`。
- 记录镜头顺序、时长、源资产、转场与版本 manifest。

### G 门禁 2：正文视觉成片

- 用户审核剧情连贯、画面逻辑、动态稳定性、需重制的单元。
- 通过后正文时间线锁定；此后改镜头时长必须提醒会影响 SRT 对齐与用户配音。
- 出 SRT 前再跑一次旁白 lint（`shots.json` / `timeline.json` 的 `cue` 字段），任何导演术语命中即停。

### H SRT

- 只覆盖正文，第一条从 `00:00:00,000` 开始；不预留片头偏移，不含任何片头/标题 cue。
- 文本只取锁定稿 `cue`；每条 ≤20 可见字；`split_srt.py` 拆条、`check_srt.py` PASS；时间轴按估算语速，注明「估算时间轴，未对真实人声校准」。
- 细则、门禁与路径见 `srt.md`。

### I 像素级 QA 与交付

- 每次拼装/重混后必须跑全片像素扫描：连续白屏/黑屏区间（≥1s）、CFR 帧序均匀性。只查文件存在、容器时长、帧数计数不算验收。
- `ffprobe` 必须确认：**恰好 1 条视频流，0 音频流、0 字幕流**；时长 = 帧数/帧率，误差 ≤1 帧。
- 交付门禁：`python shared/workflows/body-only/check_delivery.py --video <mp4> --srt <srt> --json <qa>/delivery.json` 必须 PASS。
- 助眠线白边门禁照旧；悬疑、人生体验不适用。
- 交付前核对 SRT 与视频同起点同终点、cue 数等于锁定句数、`check_srt.py` PASS；QA/manifest 存单集 `qa/`、`logs/`。
- 交付路径与命名见 `delivery.md`；交付后在 `LINE_STATE.md` 写一行当前状态与成品路径。

### J 最后回写剪映草稿（按需）

- 先确认本期是否需要片头。若前面已经锁定片头文案、画面和预设，按锁定方案执行；若没有明确方案，必须在这一步询问用户片头文案、画面素材和是否启用片头，收到确认后再生成。
- 预设映射固定如下：

| 视频线 | 剪映组合预设 | 用途 |
| --- | --- | --- |
| 悬疑线 | `恐怖主题` | 悬疑引入、钩子和标题片头；保留故障、梦核、负片等剪映原生效果 |
| 人生体验线 | `引入2` | 人生体验引入画面、文字和片头配音轨；配音由用户手动替换 |
| 助眠线（已废除） | `助眠-引入+标题图1` 或 `助眠-引入+标题图2` | 仅用户明确要求恢复助眠线时使用 |
| 音效素材 | `我的预设1` | 音频组合预设，不作为视频片头预设 |

- 复制对应预设到独立剪映草稿副本，不改写预设库和用户原草稿。
- 替换用户确认的片头图片/视频素材和文字，保留原生特效、音效、字体、动画、嵌套片段和原有配音轨。配音由用户在剪映中手动生成或替换。
- 为副本生成独立草稿登记信息，确保剪映列表可见，并在剪映中打开、保存、重开验证。
- 将可继续编辑的剪映新草稿交回用户。片头不并入默认正文 MP4，正文 SRT 不包含片头文字或时间偏移。
- 片头预设是剪映黑盒模板，WeftCut 不负责重建剪映专有效果。替换后的文字若超出原文本框承载范围，先报告并调整字号、文本框或片头时长，再进入验证。

## 3 偏离处理

以下必须提醒并等用户确认：

1. 剧本锁定后改剧情、角色关系或旁白文本；
2. 跳过关键动态审核直接合成正文；
3. 未审核正文就出 SRT 或交付；
4. 为提速换同角色形象、画风或 seed；
5. 擅自加用户未要求的转场、插帧、画质增强或画面文字；
6. 任何镜头/素材的静默降级或回退（见 §2.D）；
7. **任何违反规则或工作流的做法**：字号/样式偏离、跳过门禁、沿用旧版替代标准执行件、临时脚本绕开既定流程、重新引入片头/TTS/烧录/成品库等。
8. **把交付推过「正文视频 + SRT」**：自行产音频、烧字幕、把片头作为默认成品交付、落成品库、写成品卡或登记索引——这些已全部废止，未明确委托不得做。用户明确启用可选片头阶段时，片头只作为剪映草稿中的可编辑内容交回，不改变默认交付范围。

提醒格式：说明"会跳过/倒置哪项门禁、影响哪些已锁定产物、确认后如何执行"。未获确认不得继续。用户当次明确的口头或文字指令本身即视为该次偏离的授权，可直接执行，但仍须在运行日志记录指令原文、时间与影响范围；该授权只对当次有效，不自动成为长期规则。

## 4 当前默认技术

- 静态图：独立 GPT 图片 API，按通道路由选站。唯一事实源 `shared/image-api/channel-policy.json`（通道、单价、路由规则、门禁阈值、启停条件）；规则文档只写原则。
  - 当前策略 `v8-new2-dklb-parallel`（2026-11-15）：`new2` 与 `dkl-b` 两队并行生图，镜头/独立图请求按轮询均衡分配；同一集允许混用这两个通道。`old` 已依据 2026-11-15 同提示词对照退役，不再调用；报告见 `projects/悬疑/visual-tests/20261115-220020-old-dklb-new2/ASSESSMENT.md`。
  - 并发边界：单次 API 请求（含整张网格）固定一个通道，不拆请求；同一镜头的重试留在原通道，连续失败或通道耗尽时只把该失败镜头/未开始镜头转给另一可用通道，不重跑已完成镜头。任一通道不可用时另一队继续；两者都不可用才停止剩余任务并告知。
  - 路由由字段决定：`SHOT_PLAN` 必填 `line/step/character_ids/character_closeup/hands_visible/evidence_id/subject_class/push_ratio/needs_2048`；缺字段报错，禁止默认用某家。队列按策略文件执行镜头级轮询分配；调用端遵循分配结果，不能自行改站。
  - `dkl-b` 批量前仍须通过策略文件规定的画风小样门禁；尺寸断言、废图闸、白名单前置、统一 LUT 按策略文件执行；每次调用写 sidecar（channel/model/endpoint/price/request_id/dims/qa/fallback_from），并记录并发队列分配。
  - 密钥只从环境变量读取，不回显、不落盘。
- 动态：关键 H3 I2V（EasyCache ON，16GB 短窗分片约 5 s/段 + first_frame 接龙）；微动 Wan 2.2（EasyCache 默认关，开启须目检）；特殊物理/旧 LTX 镜用 LTX 2.3 distilled + ManualSigmas。Hunyuan 仅实验。
- 声音：**不产任何音频**。不跑 TTS、不产 WAV/分轨、不混音、不加 BGM。配音与混音由用户用自己的工具完成。
- 字幕：只出 SRT，`split_srt.py` 拆条、`check_srt.py` 验收；不生成 ASS、不做 fontsdir 烧录、不跑 ASR。
- 合成：FFmpeg；静态图推拉平移按 `../camera-motion/MOTION_GUIDELINES.md` 走 **affine 浮点亚像素后端**（60 fps 渲染、推近 ≥9%／拉远 ≥8%／横移 ≥6%），**禁止用 `zoompan`**（整数取整导致逐帧抖动）；插帧仅在用户终审后显式启用。

## 5 文档优先级

本文件是最高优先级流程说明。项目内旧文档、各集 `PROJECT_STATE` 与运行日志必须与之一致；冲突时以用户最新明确指令和本文件为准。

## 6 特殊场景与规则变更

- 单集/单镜/单次交付的特殊要求默认只是该项目局部覆盖，须写入 `PROJECT_STATE` 或运行日志。
- 局部覆盖不自动修改本文件的固定顺序、门禁或技术默认。
- 只有用户明确说"写回工作流""设为长期规则""以后都按这个"，才允许更新本文件，并记录原因、影响范围与生效日期。

## 7 会话治理

- 会话职责与规则写权限见 `governance/session-governance.md`。
- 规则中转会话收到申请后必须先问：仅某条线、还是所有线通用；未确认范围与内容前不得写入规则文件。
