# 文档组织与 MD 拆分规则

生效日期：2026-10-05

适用范围：所有已登记线路，以及共用生产、资产、运行和交付文档。项目、可复用资产、规则分别位于 projects/对应线路/、assets/对应线路/、rules/对应线路/。共用规则在 rules/shared/，工具在 shared/。目录真源为 indexes/DIRECTORY_STRUCTURE.md。

## 目标

保持文档短、职责单一、当前状态明确，并让剧本、资产、生产和历史记录可以独立回滚。文档组织不能因为线路暂时归档而停止维护。

## 文档分层

文档按以下层级维护：

1. 全局规则：跨线路长期有效的流程、权限、交付和文件组织规则。
2. 线路规则：某一条线路长期有效的内容、画风、声线和生产约束。
3. 单集故事包：某一集的剧本、旁白、世界规则、分镜和视觉事实。
4. 当前状态：当前版本、门禁、阻塞点和下一步。
5. 运行日志：命令、失败、重试、时间线和诊断信息。
6. 交付记录：只在单集 `LINE_STATE.md` 写成品路径与状态；不再建成品卡、成品索引。

不同层级不得通过复制全文保持同步。上层文档写规则，下层文档引用规则并记录局部覆盖。

## 必须拆分的时机

在出现以下任一情况时，主动拆分 MD 文件：

- 一个文件同时包含两条或以上线路的内容；
- 一个文件同时包含长期规则和单集临时决定；
- 一个文件同时包含当前状态和大量历史过程；
- 旁白正文、逐镜技术数据和生产日志混在一起；
- 图片 API 请求参数、网格拆分记录和最终资产索引混在一起；
- 文件已经需要通过目录搜索才能定位关键内容；
- 修改一个章节经常会导致不相关章节的版本号或内容变化；
- 同一信息在两个以上文件中重复维护，存在不一致风险；
- 单个 Markdown 文件超过约 300 行，或一次阅读无法明确其唯一职责。

行数只是预警指标，不是机械硬上限。即使文件较短，只要职责混杂或版本边界不清，也应拆分；如果一个结构化表格必须保持完整才能理解，则可以暂时保留，并在文件中明确其职责。

## 推荐拆分方式

线路级至少分为：

- `LINE_STATE.md`：线路当前状态；
- `README.md`：线路入口和目录说明；
- `rules/`：线路长期规则；
- `episodes/`：单集内容；
- `assets/`：线路资产索引和参考资料；
- `logs/`：线路级运行记录；
- `archive/`：旧版本和暂不使用的资产（长期归档在仓库旁 `../video-archive/`）。

单集级按需分为：

- `story/`：故事包、旁白、来源和剧情规则；
- `storyboard/`：镜头节拍、视觉事实卡和网格清单；
- `image/`：参考图、网格图、拆分图和通过图；
- `audio/`：仅用户自备配音时使用，助手不产、不读写；
- `video/`：动态镜头、视觉草稿、拼装脚本；成品在 `video/final/`，SRT 在 `video/srt/`（分目录，禁止同名相邻）；
- `qa/`：ffprobe、像素扫描、SRT 与交付检查；
- `logs/`：本集运行日志；
- `archive/`：本集旧版本。

## 当前版本与历史版本

- 使用 `CURRENT.md` 指向当前有效版本，不复制完整正文。
- 使用不可变的 `v0.1.md`、`v0.2.md` 等保存历史版本。
- 使用 `CHANGELOG.md` 记录版本变化、原因、影响范围和回滚方式。
- 当前状态文件只写当前状态，不把历史日志追加进去。
- 废弃版本保留在对应线路或单集的 `archive/`，不得继续作为生产输入。

## 拆分后的引用要求

拆分后必须在入口文件写明：

- 当前有效文件；
- 相关文件的位置；
- 文件之间的依赖关系；
- 哪个文件是唯一真源；
- 修改某文件会影响哪些下游文件。

不得为了方便阅读，把规则、旁白或资产信息复制到多个文件。需要摘要时只写摘要和链接式路径引用。

## 主动维护责任

### 统一待办入口（2026-10-07）

- 此工作区以后所有待办统一存入根目录 `todos/`，不另建线路待办真源。
- `todos/README.md` 只维护索引；具体任务按线路或主题拆成独立文件，记录状态、范围、下一步和验收条件。
- 项目状态、交接文档可引用待办路径，不重复维护任务全文；运行日志和生产资产仍放原职责目录，不搬进待办目录。
- 完成或取消后更新同一任务的状态；目录或文件职责混杂时主动拆分，避免索引增长成过程日志。

文档整理属于工作流的一部分。每次创建新线路、单集新版本、图片网格任务、生产交接或最终交付时，都要检查当前 MD 是否仍然职责单一。

发现文件职责混杂时，应先完成拆分或记录拆分计划，再继续扩大该文件内容。归档线路也必须遵守本规则；归档只改变状态，不免除文档维护责任。
