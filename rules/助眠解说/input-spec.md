# 助眠解说 · 单集输入规范 v1.0

> 目的：把“要做一集助眠”压缩成一份填好的输入单。收到输入单后，执行者从立项做到交付，中途只在硬阻塞时停。
> 地位：输入契约。它规定“你给什么、默认值是什么、什么算授权、什么情况必须停”，不重复线路规则的具体参数。
> 真源：流程 `rules/shared/video-workflow.md`；内容、视觉、音频、字幕、片头、交付分别见本目录对应模块。冲突裁决见 §7。
> 生效：2026-11-06。适用：助眠解说全部新单集；续跑单同样可用（执行模式填“续跑”并给 run 路径）。

## 0 使用方式

### 0.1 三步

1. 复制 `shared/workflows/助眠解说/EPISODE_INPUT_TEMPLATE.md`，另存为 `INPUT_<slug>.md`，放进单集根目录，作为本案输入真源。
2. 只填表格第 1–4 行（标题、主题、引入、章节大纲）；其余预填默认值，不改即按表内执行。
3. 把文件路径发我，附一句“按 input-spec 执行”。

表格的默认值就是本规范 §4 的现值。想改哪行就改哪行；不改就按表内值执行，不再逐项确认。

### 0.2 我的回执（开工前唯一一次对齐）

收到后先回一份不超过 15 行的回执：slug、题材、时长、片头型、门禁模式、预算、已套用的默认值、需要你决定的项（0–3 条）。

- B 模式：待决项为 0 时，回执后直接开工，不等确认；有待决项则只停在这些项。
- A 模式：回执后等你一句“开始”，再进 A 阶段。
- 回执之后不再重复问你已填过的字段。

回执格式示例：`slug=octopus-life｜A 动物演化｜38min｜Hook 32s｜B｜预算85张｜待决0｜已套默认：b2/0.774224/2x2/无BGM`。

### 0.3 执行者启动协议（新会话无记忆时按此读）

1. 本文件 + 输入单；
2. `rules/shared/video-workflow.md`（A→M 与门禁，最高优先级）；
3. `rules/助眠解说/production.md`；
4. 当前阶段对应模块（`narrative.md` / `visual.md` / `audio.md` / `subtitles.md` / `intro.md` / `delivery.md`）；
5. 交付前读 `rules/shared/delivery/final-delivery.md`；
6. 做片头时加载 skill `sleep-aid-intro` 与对应执行件；
7. 续跑先读 `PROJECT_STATE.md`、`CHECKPOINT.json`、最近 `REPORT_*.md`，核对实际文件与进程。

不整库通读；按阶段加载。

## 1 输入分级（你填多少，决定返工多少）

| 级别 | 你给什么 | 我做到哪 | 返工风险 |
|---|---|---|---|
| L0 选题 | 一个主题词 | 我出 2–3 个方向给你选，再进 L1 | 高 |
| L1 最小 | 主题（题材、时长我可代定） | 全流程；剧本我原创 | 中 |
| L2 标准 | 主题 + 标题 + 引入 + 大纲（必须覆盖 / 必须避免选填） | 全流程，剧本按你的骨架写 | 低 |
| L3 锁定稿 | 完整旁白（+ 事实来源） | 跳过剧本创作，直接声线与分镜 | 最低 |

L3 也要过 §5 校验：锁定稿与“必须覆盖点”冲突、事实无来源、时长与字数明显不匹配时，我先停。

## 2 必填（四项）

| # | 字段 | 写法 | 校验不通过 |
|---|---|---|---|
| 1 | 标题 | 4–40 字；可暂定但要有信息量 | 空、占位（待定 / 由你拟 / 无）→ 退回；超 40 字 → 提示 |
| 2 | 主题 | 一句话：具体对象 + 一个矛盾 / 问题 | <10 字、品类名或纯名词、无矛盾 → 退回 |
| 3 | 引入 | 正文开头 1–3 句（约 15–40 秒）；具体场景 / 问题，能直接当开头 | 空、套话（大家好 / 今天聊聊）、无具体场景 → 退回；超 200 字 → 提示压缩 |
| 4 | 章节大纲 | ≥3 章，章名 + 每章一句；或“见锁定稿”+ 路径 | <3 章、无每章一句、路径不存在 → 退回 |

必须覆盖 / 必须避免是**选填**，默认“无”；要约束就写，一行一条，过泛只提示。

校验流程：回执前先跑这 4 项；不合格只列问题清单（缺什么 / 为什么 / 怎么改），不进入剧本；改完再提交，已通过的项不重复问。空、占位、品类名、套话退回；长度偏差只提示。

其余字段都有默认值（§4），表格里已预填：时长按稿定、题材我按主题判断、参考默认公开检索、门禁默认 B、声线 b2、片头 Hook、预算 85 张、字幕 / 混音 / 封面归你。要改就在“备注”写一句。

“引入”与片头的区别：引入是正文开头，不是 Hook 片头；片头默认我写。引入可给成稿，也可给一句方向；给方向时我扩写成 1–3 句，回执里列出；方向太泛（如“随便讲讲”）退回。

题材判断：动物演化 → 第二人称（`narrative.md`）；物理数学 / 人物故事 / 生活科普 → 非第二人称；判断不了才问。

### 2.1 选题准入（我收到主题后先判）

| 检查 | 通过 | 不通过 |
|---|---|---|
| 可画面化 | 能用具体场景、物体、动作承载 | 退回或换角度，不用抽象氛围图硬配 |
| 事实密度 | 有可核验的事实、案例或历史节点 | 纯感悟、纯观点不够撑一集 |
| 助眠适配 | 低刺激、无惊吓、无医疗承诺、不做灾难倒计时 | 调整表述或退回 |
| 时长承载 | 内容能撑起目标时长且不注水 | 缩短时长或换题 |
| 素材版权 | 文本、图、音频可用 | 换素材 |

示例：“讲睡眠”不合格；“人在没有钟表的地下洞穴里，身体如何重新定义一天”合格。

## 3 授权（决定能不能“到结束”）

### 3.1 门禁模式

| 模式 | 停点 | 适用 |
|---|---|---|
| A 分段确认 | E 关键动态、G 正文成片、J 片头（J 内先确认 H 文案，再生成，再验收） | 想逐段把关；规则默认 |
| B 一次性授权 | 不停人工门禁；三关以 QA + 抽帧目检替代，成片统一验收 | “给文档就做完”；本规范主用途 |
| 混合 | 在“备注”写明哪几关停 | 只关心其中一段 |

选型一句话：想一次交付、能接受成片后统一返工 → B；想亲手把关关键动态 / 正文 / 片头 → A。表格版默认 B；要 A 就在“备注”写“分段确认”。

B 模式的效力与边界：

- 它是你对 E/G/J 三道人工门禁的**一次性书面批准**，仅对本次输入单有效。依据：用户最新明确指令优先；先例 `life-manual` 2026-10-24“直接开始做，直到这个视频完成”（`编剧3/PROJECT_STATE.md`）。
- 它**不取消**验收标准：gate QA、G1–G6（如代做字幕）、像素门禁、事实核验、交付终检照跑，证据写进 `qa/` 与终报。
- 它**不自动批准**镜头/素材降级回退（§3.2），除非输入单的降级项为“允许并披露”（表格默认）。
- 它**不豁免** §5.2 的 8 种硬停。B 模式的意思是“不停在人工门禁”，不是“永不停”。
- 替代证据要可复查：每关留 `qa/gate-<n>/`（抽帧、指标、通过 / flag 清单），终报给路径。
- B 模式构成对 `video-workflow.md` 三道人工门禁的偏离；偏离点、影响与你的输入单确认记入 `PROJECT_STATE.md` 的“授权与门禁”一节（写法参照 `编剧3/PROJECT_STATE.md`）。

### 3.2 降级与回退

| 选项 | 含义 | 触发停的条件 |
|---|---|---|
| 停（规范默认） | 任何 I2V→静帧、换镜、模型降档、时长不足换备选，先汇总清单等我批 | 全部 |
| 允许并披露（表格预填） | 允许在“不改变关键事实、不改变交付时长、单镜不超原计划 ±20%”内回退，逐条登记并在终报披露 | 关键事实、整段结构、>10% 镜头、累计 >30 s |

（±20%、10%、30 s 是本规范的放行阈值，可按输入单收紧；不是线路规则。）

要真正做到“给文档就做完”，需要 **B 模式 + 允许并披露**；表格版已把这两项设为默认，在“备注”写“分段确认”或“回退先停”即回到严格模式。

无论哪种，都不允许静默回退（`video-workflow.md` §2.D）。注意：“停”是停在“回退审批点”，不是拒绝回退；技术上的默认替代仍是高清静帧推拉（`project-rules.md`、`visual.md`），批准后才执行。

### 3.3 委托项（默认按规则留给用户）

| 项 | 默认 | 委托给我时 |
|---|---|---|
| 字幕 | 用户 Subtitle Edit | FunASR 字级对齐 + style_r4 + G1–G6；不另写文案 |
| 混音 | 用户手动 | 旁白优先；BGM 仅在明确要求时用 `SLEEP-BGM-UNIFIED-001`；独立 stem |
| 封面 | 用户自制/定稿 | 按 `delivery.md` 出横竖两版，文字后期排版；属内部资产，不自动进最终交付 |
| 发布文案 | 用户 | 按 `delivery.md` 的发布口径 |

### 3.4 预算与授权

- **生图 API**：填上限（张，2x2 网格图；1 张 = 1 次调用 = 最多 4 个镜头位）。35–45 分钟基准 60–85 张；填上限即视为对该上限内的批准，超出必须停（`image-grid-generation.md`）。
- **单位口径**：预算按“张 2x2 网格图”算，不按单镜成品图。85 张网格图最多 340 格，扣单镜、重试与空格后约 250–270 个可用镜头；若按 85 张单镜成品图算，只有 20–25 分钟，不是本线路的预算口径。
- **接口异常**：403 / 余额不足 / 鉴权失败视为外部依赖不可用，停并报账，不自动换接口、换模型或降档。密钥只从环境变量读取，不回显、不落盘。
- **GPU**：可填小时上限；不填则按本机队列推进，不设硬上限，但每阶段报实际占用。
- **外部检索**：允许公开网络（默认，需引用）/ 仅用户材料 / 禁止。
- **素材授权**：你提供的文本、图、音频须注明原创 / 已授权 / 公共领域；未注明时我只做引用，不复制进成片。
- **事实级别**：严格（关键事实逐条有来源，缺则停）/ 标准（默认，FACT_NOTES 标注来源与争议）/ 轻（只标高风险）。

## 5 校验与停止

### 5.1 开工前校验

硬失败（退回，不开工）：

1. 缺 §2 第 1–4 项或必填校验不过；
2. 主题与题材矛盾（例：题材 A 却要求“不出现动物”）；
3. 锁定稿与“必须覆盖点”冲突；
4. 要求使用未授权素材；
5. 事实“严格”级但无来源；
6. 预算为 0 或明确禁止生图，却要求成片；
7. 交付要求与规则冲突且未在“备注”写明偏离；
8. 选题准入（§2.1）不过，且无法在不改变主题的前提下修正。

软缺失（套默认值，回执里列出）：片头型、视觉参考、母题、声线、字幕 / 混音归属、截止时间。

### 5.2 执行中必须停的 8 种情况

| # | 情况 | 我先做什么 | 你至少要回什么 |
|---|---|---|---|
| 1 | 关键事实无法核实 | 停在该镜 / 该段，保留已做部分 | 删 / 改保守表述 / 给来源 |
| 2 | 缺凭据、API、GPU 且无替代 | 保存请求与日志，转做可独立推进的 CPU 工作 | 补凭据或改期 |
| 3 | 要改已锁定文稿 / 声线 / 时长 | 列出受影响的配音、字幕、片头、时间轴 | 批准重做范围 |
| 4 | 回退影响关键事实或超 §3.2 阈值 | 汇总镜头、原因、影响时长 | 接受披露 / 重做 / 换方案 |
| 5 | 预算超上限 | 停，报实际与差额 | 追加 / 降镜数 / 停在当前 |
| 6 | 版权 / 许可风险 | 停用该素材，找替代 | 授权证明 / 换素材 |
| 7 | 硬门禁不过且无法修复 | 保留失败版本与 QA | 接受 flag / 重做 |
| 8 | 输入单内部自相矛盾 | 列冲突项，不猜 | 二选一 |

除这 8 种，B 模式下我不以“等你确认”结束任务。

### 5.3 我不问、自行决定并记录的事

风格细节、镜头选择与转场、章节顺序微调、字体排版、文件名、日志格式、常规错误修复（重试、单镜重跑、脚本修复）、并行调度、缓存与临时目录。

判断标准：不改变文本、声线、时长、事实与交付定义。

| H 片头文案 | 两拍钩子 + 过渡旁白 + 四字标题 | N 按正文实测；先锁文案再配音；A 模式下先确认文案再生成 | 含在 J |
| I 片头制作 | `intro/batch-*/clean-intro.mp4`、`timeline.json`、manifest、gate QA | 默认 Hook v1.0；≥2 图；大字只用 ASS 矢量 | 是 |
| J 门禁 3 | 片头 QA + 抽帧 | `intro.md` §8 六条 | 是 |
| K 拼接 | 片头 + 正文；`narration.wav` 同步重建 | 正文起点后移片头实测时长 | 否 |
| L 音频 / 字幕 | 分段 VO、章时间轴、字幕（如委托）、混音 stem | 0.774224；G1–G6；BGM 可选 | 否 |
| M 交付 | clean + narration、像素 QA、终报、manifest | 两件套 ±1 帧；登记需你确认 | 否 |

每阶段结束写一条续跑记录，只含五项：当前阶段、已完成、运行中任务、下一条具体命令、当前阻塞（无则空）。计划与状态分开，原子写入。

Gate QA 最低项：E 看身份 / 光影 / 几何 / 接缝；G 看剧情连贯 / 镜头稳定 / 时间线；J 按 `intro.md` §8。

续跑不重做已验收素材：先读记录、核对文件与进程，从未完成项接续；已完成章节的配音、静帧、动态、字幕可复用。

## 7 冲突裁决

| 冲突 | 裁决 |
|---|---|
| 输入单 vs 规则 | 输入单显式勾选偏离 → 按输入单并记录；未勾选 → 按规则，必要时停 |
| 输入单 vs 你后续口头 | 后续口头优先，记 `CHANGELOG`，重算受影响产物 |
| 输入单内部矛盾 | 停，列冲突（§5.2-8） |
| 锁定稿 vs 必须覆盖点 | 停；不擅自改稿 |
| 目标时长 vs 文稿 | 文稿优先；实际时长报偏差；不加速朗读、不删句凑时长 |
| 片头时长 vs 类型上限 | 优先调文案；仍超则报你决定，不擅自加速 |

## 9 变更管理

- **锁定后改文本**：重跑 A/B/L 的受影响单元；片头若含该句也重做；字幕重对齐。
- **改时长 / 片头**：时间轴、字幕、BGM 循环长度全部重算；不许整体平移字幕。
- **改声线**：全片重配；不局部替换、不用变速修节奏。
- **新指令与输入单冲突**：新指令优先，写 `CHANGELOG.md` 并说明返工范围。
- **已交付版本不覆盖**：旧版进 `archive/`。
