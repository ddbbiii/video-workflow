## 加载顺序

0. 新单/续跑：先 `input-spec.md`，确认输入单与授权模式后再开工
1. 全局流程：`../../rules/shared/video-workflow.md`（A→M 与三道人工门禁，最高优先级）
2. 本目录：先 `production.md`，再按当前阶段只读对应模块
3. 执行件：`shared/workflows/助眠解说/`（命令与参数，不含规则）
4. 工艺手册：skill `sleep-aid-intro`（脚本序列与踩坑）

## 边界

- 全局规则（流程、交付定义、生图规范、成本口径）在 `rules/shared/`，本目录不复制；冲突时以用户最新指令与 `video-workflow.md` 为准。
- 本目录不写单集特例；单集覆盖写进该集 `PROJECT_STATE` 或运行日志。
- **执行前先加载当前阶段对应的规则与资产**（字幕必须先读 style_r4 `CURRENT.md` 与 style 行，片头先读 `intro.md` 的当前默认型）。任何与规则不一致的做法都算偏离：先说明偏离点、影响与替代方案，等用户明确同意后再执行，并记录确认；不得先做后报。
- 修改本目录需用户明确要求，改动记入 `rules/shared/README.md` 的“最近写回”。

## 扩展约定

- 新增主题就新增一份文件，并在上表加一行；不改其他文件。
- BGM 库建成后，曲目检索走 `assets/助眠解说/audio/bgm/` 的每曲 md 与索引，`audio.md` 只留选型原则与入口。
- 跨文件引用写“文件 + 章节”，不写死行号。
